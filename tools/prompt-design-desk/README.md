# 场景主创提示词评审台

打开 scene-prompt-design-desk.html 即可离线使用。本版共 33 位：25 位新链路设计、2 位已退出新链路的共同层、6 位历史顶层提示词。25 位中含 1 位单独的技术整理步骤。

1. 选择提示词位，左侧显示关联旧稿全文。通过“查看旧提示词”“查看当前设计”或来源下拉框切换。
2. 右侧是可修改的填写稿。“通过当前填写”确认当前正文。
3. 认可旧稿时，点“采用此旧稿并通过”。也可组合多份关联旧稿，或撤销上次采用。
4. 修改已通过的正文会取消通过；备注修改保留正文决定。
5. 导出 JSON 或复制结构化文本，交回整理装载。导出含全文、备注、来源版本与摘要、通过时的原文及历史位标记。

你修改、采用、批注或通过的浏览器稿件保留，可以在左侧查看新稿后决定采用。未修改的旧内置初稿自动刷新为本版文字，新位载入本版初稿。主动导入的内容保持原文。旧版“可整理”标记需要重新确认通过。导入后可撤销，未包含的位保留。更换设备前导出备份。

页面展示当前内置稿、旧链路稿，以及此次自然文本重构前的完整快照，共 97 份来源。全局和作品自定义稿可导入或粘贴。来源按文本展示。采用旧稿保持原文，后续装载时再核对它与新拼装方式的关系。

## 当前设计

角色系统模板保留版本 3 的十六区块结构。主创填卡任务以鲜明、极度风格化的人物辨识度为方向。较早带前言的角色模板仍可查看；已有草稿中的同一段前言按精确匹配迁移，迁移后重新评审。

四类领域创作者分别进入环境经验、人物可见存在、事件叙述和场面构图，初始化模板直接作为系统提示词。每类各有一个 `【文风】` 自由栏。主创与文学编辑的身份模板也各有一个文风栏。主创通过每次委托的 `style_direction` 填写四类取材伙伴的文风。

创作、取材、审读和填卡以自然文字完成，随后单独整理为系统记录。技术整理位 `scene.v2.transport.extractor` 展示在独立分组，可供评审。程序留存文学原文，并校验正文、候选文字及角色卡区块的逐字提取。

## 评审与运行

进度中的“新链路”只统计 25 位当前设计；8 位历史稿保留供比较和采用。旧独立 performance.plan 作为来源可读。

通过决定保存于浏览器和导出文件。运行开关保持默认关闭，旧交易继续使用各自快照。接下来按你的评审结果整理装载，并以冲突、日常、空间调度和设定揭示场景做真实模型对照。

角色对话入口位于应用的作品档案室。它使用独立角色卡、已知档案挂载、场景上下文与对话历史。这个离线评审页面用于文案设计；角色对话由应用服务提供。

DOM 操作、来源保真、导入导出已验证。浏览器工具策略拒绝本地页面访问，桌面与手机截图、实际重叠和横向溢出检查尚待完成。

## 构建与验证

~~~powershell

python tools/prompt-design-desk/build_snapshot.py --output <输出目录>
node tools/prompt-design-desk/test_desk.cjs <输出目录>/scene-prompt-design-desk.html
~~~
