# Pi Worker 专业化成本收益决策

状态：Accepted with measurement gates
基线版本：ArcVellum v0.99.3
日期：2026-08-31

## 结论

ArcVellum 继续建设 Pi Worker 的专业能力，但采用“薄领域内核、强确定性宿主、量化后扩张”的路线。

当前 Pi Worker 已经具备进程隔离、任务包、双工作区、受限读写工具、取消、无进展检测、预检、有限修复与 Engine Gate 等关键基础。近期收益最高的工作集中在四个方面：

1. 将任务类型、产物类型、证据策略、执行策略、语义合同与推理档位编译成精简的 `LiteraryTaskSpec`。
2. 区分 `direct-submit` 与 `evidence-then-submit` 两类执行策略，避免所有任务都进入同一种工具循环。
3. 让模型主要提交文学语义载荷，由宿主代码补齐可确定生成的执行元数据、来源和完成凭据。
4. 修复提示词宣称支持按需读取、常规 Worker 循环却优先强制写出的合同不一致，并以真实任务验证读取次数、Provider 往返与一次通过率。

这轮专业化保持 Studio/CLI 对任务状态、正式门禁、Canon、Promotion 和事务写回的唯一权威。Pi Worker 负责理解与执行已经编译的文学任务，不建立第二套工作流。

## 已有证据

Prompt v3 已经取得显著的固定开销收益。场景正文的合并提示词由 189,908 字符降至 29,218 字符，缩减约 84.6%。现有 A/B 样本显示：

| 任务类型 | 指标 | Prompt v2 | Prompt v3 | 变化 |
| --- | ---: | ---: | ---: | ---: |
| 结构化任务 | 输入 Token | 13,758 | 8,531 | -38% |
| 结构化任务 | 总 Token | 53,931 | 37,001 | -31% |
| 结构化任务 | 成本 | $0.003985 | $0.002862 | -28% |
| 结构化任务 | 时长 | 68.69 s | 56.85 s | -17% |
| 审查任务 | 输入 Token | 17,669 | 13,720 | -22% |
| 审查任务 | 总 Token | 68,013 | 57,215 | -16% |
| 审查任务 | 成本 | $0.005097 | $0.004886 | -4% |
| 审查任务 | 时长 | 72.72 s | 77.67 s | +7% |

数据表明，压缩提示词能够降低 Token，仍需通过执行策略、工具往返与失败恢复继续改善真实耗时和成功成本。廉价模型下的单次直接费用很低，专业化的主要价值来自吞吐、鲁棒性、注意力负担、一次通过率和本地小模型适配能力。

## 投资边界

### 当前应做

- 建立 `LiteraryTaskSpec` 的投影与版本化 Schema。
- 保持任务编排和 Gate 在 Engine/Studio，Pi 只解释执行策略。
- 用少量领域语义明确的工具能力替代重复协议文本。
- 将证据按核心、摘要、按需三层投递，并保证提示词与工具租约一致。
- 对结构化、审查、正文三类任务分别建立成本、时延、质量和通过率基线。
- 为一次失败后的有限修复保留完整原因、产物差异和确定性预检结果。

### 当前暂缓

- 在 TypeScript Worker 内复制 CLI 状态机、Canon Policy 或 Promotion 规则。
- 为每一种文学概念创建一个工具，造成工具面和维护成本膨胀。
- 将完整聊天历史长期塞入每次模型请求。
- 让 Pi Worker 自行拥有跨任务编排、并发调度和正式写回权。
- 在缺少测量证据时引入复杂的多 Agent 协作系统。
- 以全面重写替代现有已经稳定的任务包、沙箱与预检链路。

## 最小高收益实施闭环

```text
Engine TaskPackage
  -> Studio LiteraryTaskSpec Compiler
  -> Context / Evidence Broker
  -> Pi Worker Strategy: direct-submit | evidence-then-submit
  -> Model semantic payload
  -> Local shape and artifact validation
  -> Studio deterministic preflight
  -> Transactional writeback
  -> Engine Gate / Promotion / Canon apply
```

第一阶段只覆盖三类高频任务：结构化资产、语义审查、场景正文。每一类都要保留当前实现作为对照组。

## 继续投资门槛

完成最小闭环后，满足以下条件才扩大持久会话、只读子 Agent 或更多领域工具：

- 结构化与审查任务平均总 Token 至少下降 15%。
- 正文任务平均总 Token 至少下降 8%，盲评质量没有下降。
- 每项任务平均 Provider 往返至少减少 1 次，或首次 Gate 通过率获得同等可验证提升。
- 修复轮次下降至少 20%。
- P50 与 P95 完成时延均有稳定改善。
- Engine/Studio 的唯一权威没有被削弱，未产生双重状态或双重写回路径。

若数据只证明代码复杂度上升而收益不足，专业化停留在 `LiteraryTaskSpec + 双执行策略 + 语义载荷提交`，不继续扩张。

## 架构含义

Pi Worker 的长期定位是 ArcVellum 的受控文学任务解释器。它可以拥有文学任务感知、按需证据读取、角色化创作策略和有限恢复能力；项目事实、流程合法性和正式发布身份继续由 Engine/Studio 管理。这个边界让创作能力可以迭代，让项目权力保持单一来源，也让每次性能投入都能用真实作品闭环衡量。
