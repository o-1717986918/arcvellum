# ArcVellum 活字天穹设计审查

## 审查对象

- `visual-orrery`：Pixi.js、全向程序天穹、空间构型与中键平移。
- `arcvellum/frontend`：原生 WebGL2 文学观测台、DOM 文字标签、镜头飞行与叙事仪表。
- 当前 ArcVellum：Vue、Pixi.js、真实项目投影、关系线、窗口、阅读器、决策与工作流。

第二套参考必须通过 `/ui/` 正式入口运行。静态打开不能加载其样式、模块和演示数据，不构成有效视觉证据。

## 批判性结论

第一套最强的是空间连续感。背景不只是图片，而是能随镜头响应的全天域；中键移动也比左键拖动更不容易与节点选择冲突。它的风险是球体、环和高亮在聚焦状态下容易过度膨胀，文学信息会退居装饰之后。

第二套最强的是“文字就是天体”的设计立场。中文标题直接成为叙事星座，比统一圆形图标更有文学辨识度。但正式运行也暴露了缺点：远景标题大量碰撞，字号与镜头距离耦合过强，决策卡会遮断主视觉。纯文字不是天然高级，必须有语义层级、屏幕空间碰撞管理和视距规则。

当前 ArcVellum 的优势是工程事实完整。它已经拥有真实投影、章节目录、人物关系、证据线、状态、窗口和阅读器，不能为了视觉重写成一个演示型 WebGL 应用。其主要不足是节点像通用软件按钮，固定背景削弱了全向空间感，左键拖动也会和内容选择竞争。

## 设计决策

采用“活字天穹”混合语言：

- 章节：文字主星。远景显示章节索引，近景显示完整标题。
- 场景：轻量文字星点。远景只留星点，近景展开名称。
- 人物：姓名与人物色光，不使用统一圆形头像按钮。
- 分支、承诺、审查、Canon：保留极简语义符号，避免所有类型退化成同一种文字。
- 关系：继续使用现有曲线、证据流和人物线，不复制参考项目的渲染代码。
- 天穹：所有构型共享确定性双层星野；构型只改变叙事空间语法，不再决定是否“像星空”。
- 默认构型：新会话以三维星簇球壳打开；书脊保留为可切换的精确时间线，章节目录始终负责顺序导航。

## 代码机制迁移矩阵

| 参考机制 | 结论 | ArcVellum 落点 |
| --- | --- | --- |
| `visual-orrery/core/sky.ts` 的三层星等、星云、银河与极光 | 改造采用 | 不复制 GLSL；由 `celestialCanopy.ts` 在现有 Pixi 远/中/近景层实现星等分布、星云壳、银河光带、星尘和亮星芒 |
| `visual-orrery/core/grammars.ts` 的“章节星核 + 场景局部星簇” | 采用 | `layoutEngine.ts` 以真实 `chapter_id` 建核，章节内场景按黄金角轨道分布；缺少章节元数据的旧项目仍保持连续时序 |
| `visual-orrery` 的星簇球壳构型 | 改造采用 | `constellation` 使用可扩展的纬带章核；章核围绕天球分层，场景沿本章黄金角轨道分布，既保留实验稿的星簇层次，又不写死卷数 |
| 实验稿的浑仪环、受光弧和仪器景 | 部分采用 | 天幕只保留稀疏仪轨和构型轮廓，避免环体盖过叙事节点 |
| 第二实验稿的文字星体与色温类型区分 | 采用 | 章节、场景、人物继续使用文字星体；正式、活动、计划通过亮度层级而非隐藏表达 |
| 第二实验稿的光桥、承诺线、人物线 | 保留现有实现 | 现有关系投影比实验稿的数据契约更完整，只加强视觉，不替换关系内核 |
| 两个实验稿按距离直接隐藏标签/雾化远景 | 拒绝 | LOD 只决定是否显示文字；所有屏内节点都保留清晰、可点击、可访问的星体标记 |
| 原生 WebGL2 渲染内核、后处理和自研矩阵栈 | 拒绝 | 与 Vue/Pixi 产品内核重复，维护成本和桌面兼容风险高 |

## 两个实验稿的代码级视觉审阅

### `visual-orrery`

| 文件/机制 | 评价 | 处理 |
| --- | --- | --- |
| `core/sky.ts`：三层星野、星等分布、闪烁、FBM 星云、银河、极光 | 天幕完整、空间连续，是第一实验稿最值得保留的机制 | 概念迁入 `celestialCanopy.ts`；使用 Pixi 确定性星场、星河、星云丝带、极光流和仪轨，不复制 shader |
| `core/grammars.ts`：浑仪、星河、层环、星簇、回环、观台 | 空间语义明确，但固定三卷、每卷四章，不适用于任意作品 | 保留“构型是语法”的思想；用真实章节数量、`chapter_id`、节奏和时间信息驱动现有六构型 |
| `core/scenery.ts`：投影圆环、受光弧、台阶、极轴、日晷 | 能给伪 3D 提供体积参照，但密度过高会盖住关系 | 只保留稀疏仪轨、星簇边界和构型轮廓，继续置于非交互景深层 |
| `core/rig.ts`：轨道镜头、平移、缩放、电影式飞行 | 输入分工清楚，空间手感好 | 复用思想：空白左键旋转、中键平移、滚轮缩放；镜头仍由 ArcVellum 的 quaternion 与任务焦点系统管理 |
| `core/vec.ts`：向量、四元数、投影数学 | 算法可靠，但项目已有等价实现 | 不复制；保留 `parallaxProjection.ts` 单一数学源，避免两套坐标内核 |
| 固定演示节点与体积配置 | 适合展示，不适合工程项目 | 拒绝；所有节点、簇、关系和完成状态继续来自正式投影 |

### `arcvellum/frontend`

| 文件/机制 | 评价 | 处理 |
| --- | --- | --- |
| `gfx/sky.js`：WebGL2 全天幕、噪声星云、银河、尘埃 | 视觉密度好，但会形成第二渲染内核 | 只吸收分层与色温原则，落在 `celestialCanopy.ts` |
| `gfx/grammars.js`：章组、局部场景轨道、球面/旋臂构型 | “章核 + 场景局部轨道”非常适合长篇项目 | 落在 `layoutEngine.ts`；采用纬带章核、真实章节分组、局部黄金角轨道和确定性布局 |
| `gfx/scene.js`、`materials.js`：章节行星、场景星体、人物宝石、关系带 | 类型区分清楚，但实体几何过多会重现“三层图形叠加”问题 | 章节、场景、人物改为活字星体；仅分支、承诺、审查、Canon 保留小型语义符号 |
| `gfx/labels.js`：DOM 标签和视距隐藏 | DOM 标签便于点击和无障碍；按距离隐藏会造成用户报告的“节点虚化” | 保留 DOM 命中层，拒绝节点隐藏；碰撞只隐藏副文案，始终保留明亮星核 |
| `gfx/postfx.js`：Bloom、god rays、色差、ACES、颗粒 | Bloom 与色调映射有价值；色差和重后处理不利于正文阅读与桌面兼容 | 用局部 CSS/Pixi 光晕代替全屏后处理，不引入新的 post-FX pipeline |
| 镜头飞行与节点聚焦 | 反馈明确，但单节点飞行容易丢失全书上下文 | 保留聚焦动画，同时默认先完整取景；底部章节目录承担从全书到局部的导航 |
| HUD 与演示数据 | 有展示性，但不是项目管理客户端 | 不迁移；保留 ArcVellum 的推进、决策、规则、健康、交付、阅读器与真实 Agent 状态 |

代码迁移遵循“借思想、不复制源码”：没有引入实验稿文件、GLSL、矩阵栈或演示数据，也没有建立新的渲染运行时。

## 本轮实现约束

- 标签碰撞不能删除节点，只能将节点降为清晰星点。
- 时间窗、聚焦和热力层不能把非焦点节点压到不可辨认；它们改用色温、光晕和文字密度表达。
- 章节是场景簇的真实星核；章节、场景、人物与证据仍由同一正式投影驱动。
- 背景元素随现有远/中/近景层产生视差，但不接管项目选择、命中测试或关系事实。
- 100、300、1000 节点必须保持确定性、有限坐标、可导航和可复现。

## 交互契约

- 左键单击：选择文字或节点。
- 左键拖动空白天穹：无角度限制地调整伪 3D 朝向。
- 中键拖动：移动叙事天穹。
- `Alt + 中键拖动`：左键旋转的等价操作。
- 滚轮：缩放。
- 双击文字节点：聚焦并打开详情。

## 布局与辨识度

- 借鉴实验星仪的空间语法，而不复制其坐标：章节是稳定星核，场景围绕章节重心形成局部星簇，人物和证据仍占据独立关系轨层。
- 默认首屏使用完整构型取景，不再只截取开篇数个节点；章节、场景视图仍呈现全书，只提高节点粒度。
- 星簇使用两到三条天球纬带组织章节。章节数量变化时自动计算每带容量，避免把十章以上作品挤成中心点团。
- 屏幕空间碰撞仅抑制文字副本；章节编号、场景星核、人物星核和全部关系事实保持可见。
- 观察时点只改变有限的明暗层级，不再把远景节点压成近乎不可见的雾点。
- 计划中节点保持可读；完成状态通过更强亮度与光晕区分，而不是靠隐藏未完成内容制造对比。

## 本轮视觉验收

- 100 场景、10 章节作品：书级首屏能同时看到至少 6 个章节核，实际截图显示全部 10 个。
- 章节与场景视图：全书 10 个章节簇均保留，章核编号可见，场景以明亮星点围绕本章聚集。
- 五套主题与全书/章节/场景/人物四种语义焦点通过 Playwright 实际截图检查。
- 80 个完全重叠节点的单元测试确认：碰撞降级不会删除任何节点，只压缩文字。

该契约把“操作内容”和“操作空间”分开，同时保留高级空间观察能力。

## 不采用的方案

- 不把全部节点改成大号纯文字。它会造成碰撞，并消除节点类型差异。
- 不把当前 Vue/Pixi 架构替换为原生 WebGL2 单页实现。参考项目是视觉原型，缺少 ArcVellum 的产品状态和工程契约。
- 不复制参考项目的 shader、相机或节点代码。本轮只借用全向天穹、文字天体和输入分工的思想。
- 不让装饰压过正文、关系和进度。星空必须响应真实作品状态。

## 后续扩展接口

后续可将节点排布升级为 Agent 提议、确定性编译器验收的 `SpatialCompositionPlan`。Agent 只决定语义分组、视觉重心和留白意图；布局引擎仍负责最小间距、碰撞、全书目录连续性、可访问性和稳定复现。
