# ArcVellum 活字天穹设计审查

## 审查对象

- `visual-orrery`：Pixi.js、全向程序天穹、空间构型与中键平移。
- `arcvellum/frontend`：原生 WebGL2 文学观测台、DOM 文字标签、镜头飞行与叙事仪表。
- 当前 ArcVellum：Vue、Pixi.js、真实项目投影、关系线、窗口、阅读器、决策与工作流。

第二套参考必须通过 `/ui/` 正式入口运行。静态打开不能加载其样式、模块和演示数据，不构成有效视觉证据。

## 批判性结论

第一套最强的是空间连续感。背景不只是图片，而是能随镜头响应的全天域；中键移动也比左键拖动更不容易与节点选择冲突。它的风险是球体、环和高亮在聚焦状态下容易过度膨胀，文学信息会退居装饰之后。

第二套最强的是“文字就是天体”的设计立场。中文标题直接成为叙事星座，比统一圆形图标更有文学辨识度。但正式运行也暴露了缺点：远景标题大量碰撞，字号与镜头距离耦合过强，决策卡会遮断主视觉。纯文字不是天然高级，必须有语义层级、屏幕空间碰撞管理和视距规则。

当前 ArcVellum 的优势是工程事实完整。它已经拥有真实投影、章节目录、人物关系、证据线、状态、窗口和阅读器，不能为了视觉重写成一个演示型 WebGL 应用。其主要不足是节点像通用软件按钮，固定背景削弱了全向空间感，左键拖动也会和内容选择竞争。

## 设计决策

采用“活字天穹”混合语言：

- 章节：文字主星。远景显示章节索引，近景显示完整标题。
- 场景：轻量文字星点。远景只留星点，近景展开名称。
- 人物：姓名与人物色光，不使用统一圆形头像按钮。
- 分支、承诺、审查、Canon：保留极简语义符号，避免所有类型退化成同一种文字。
- 关系：继续使用现有曲线、证据流和人物线，不复制参考项目的渲染代码。
- 天穹：所有构型共享确定性双层星野；构型只改变叙事空间语法，不再决定是否“像星空”。

## 交互契约

- 左键：选择文字或节点，不平移画布。
- 中键拖动：移动叙事天穹。
- `Alt + 中键拖动`：无角度限制地调整伪 3D 朝向。
- 滚轮：缩放。
- 双击文字节点：聚焦并打开详情。

该契约把“操作内容”和“操作空间”分开，同时保留高级空间观察能力。

## 不采用的方案

- 不把全部节点改成大号纯文字。它会造成碰撞，并消除节点类型差异。
- 不把当前 Vue/Pixi 架构替换为原生 WebGL2 单页实现。参考项目是视觉原型，缺少 ArcVellum 的产品状态和工程契约。
- 不复制参考项目的 shader、相机或节点代码。本轮只借用全向天穹、文字天体和输入分工的思想。
- 不让装饰压过正文、关系和进度。星空必须响应真实作品状态。

## 后续扩展接口

后续可将节点排布升级为 Agent 提议、确定性编译器验收的 `SpatialCompositionPlan`。Agent 只决定语义分组、视觉重心和留白意图；布局引擎仍负责最小间距、碰撞、全书目录连续性、可访问性和稳定复现。
