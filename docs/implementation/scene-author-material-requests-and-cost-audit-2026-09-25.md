# 主创按需素材请求与创作调用审计

状态：2026-09-25，已实施并完成自动化回归；尚未做真实模型的正式场景试跑。适用 `lean-v2` 场景事务；正式 Engine TaskPackage 路线的 Gate 不在本批修改。

## Module Change Packet A：创作合同

```yaml
module_change_packet:
  objective: "主创可在写作与修订阶段提出角色续演或环境补写请求"
  primary_module: "Engine literary/scene/roleplay/interaction.py"
  public_entry: "Engine public literary 的素材请求解析与补充提示渲染"
  variation_point: "请求哪位角色、哪项空间观察及本场情境，由主创决定"
  inputs: ["SceneBrief", "现有候选素材", "主创请求"]
  outputs: ["有界且可归属的角色/环境候选", "供同一主创继续写作的素材"]
  invariants: ["角色仍由原角色会话生成言行", "环境仍不产角色言行", "唯一正式正文作者仍是主创", "Canon 与审查 Gate 不变"]
  allowed_dependencies: ["Engine literary scene contracts", "Studio 场景事务 adapter"]
  forbidden_dependencies: ["Provider SDK", "项目写入", "第二套场景 Gate"]
  tests: ["请求解析", "原角色会话续演", "环境补写", "创作与修订继续"]
  rollback_unit: "本批聚焦 diff；工作树既有改动不混合提交"
  documentation: ["本文"]
```

## Module Change Packet B：调用编排

```yaml
module_change_packet:
  objective: "省去开场编排之后重复的第一轮导演模型调用"
  primary_module: "Studio runtimes/scene_interaction.py"
  public_entry: "perform_scene_interaction"
  variation_point: "开场编排同时给出 opening_direction；后续轮次仍依据真实公开言行决定"
  inputs: ["已校验的 Scene Performance Plan", "角色原会话"]
  outputs: ["按真实轮次的候选素材", "可续演的场景会话状态"]
  invariants: ["开场人物由主创而非轮询决定", "多人和单人场景保持支持", "原角色同场会话延续"]
  allowed_dependencies: ["Engine public literary", "Pi Worker conversation gateway"]
  forbidden_dependencies: ["额外角色任务单路线", "固定轮流说话", "候选直接晋升正文"]
  tests: ["首轮不重复调用导演", "后续仍基于公开日志调用", "场景事务回归"]
  rollback_unit: "本批聚焦 diff；工作树既有改动不混合提交"
  documentation: ["本文及执行记录"]
```

## 调用盘点（修改前）

| 调用 | 当前用途 | 判断 |
|---|---|---|
| 开场编排 | 节拍、角色初始化与处境、环境初始化 | 保留；同时给出开场发言方向 |
| 环境写手 | 候选环境段落，并向角色提供空间素材 | 保留；主创可按需补写 |
| 第一轮导演 | 在空公开日志上重新选人物与节拍 | 与开场编排重叠，合并 |
| 后续轮导演 | 依据真实角色言行决定谁回应及何时结束 | 保留，具有新信息 |
| 角色扮演 | 同一角色持久会话中的言行候选 | 保留，人物声音来源 |
| 主创正文与字数续写 | 正文、情节、设定及篇幅 | 保留；字数续写仅缺口时触发 |
| 外显动作来源审计 | 核对“角色一级生成”要求 | 保留，避免主创越过角色来源 |
| 独立审查与证据修订 | 文学质量和正式晋升链 | 保留，非重复素材调用 |

主创只在主动发出请求时增加素材调用。若请求无法兑现，向主创明确返回未完成原因，不把已有候选伪装为新续演。`escalation_reasons` 仍用于未决事实或人工升级；它不再被提示词误称为角色续演入口。

## 实施结果与调用成本

- 主创在初稿、审查后的修订、一级角色言行来源修订三个写作节点，均可返回 `material_requests`，指定角色、节拍和眼前处境，或指定环境观察。编排器取得新增候选后，将材料交回主创继续写作；正式 prose、设定展开、宏观情节、世界状态变化、视角心理、环境融合与 SceneDelta 仍由主创负责。角色请求延续该角色在本场的初始化与历史，环境请求使用既定六区块初始化。
- 开场编排同时产出 `opening_direction`，删去原本针对空公开日志的首轮导演调用。若本场实际发生 K 轮角色回应，导演调用由原来的 K+1 次变成 K 次，后续仍逐轮读取新增言行。导演提示只带节拍、任务、开场方向和事实空位；给主创的材料只带节拍、公开轮次、角色条目和环境候选，不再反复携带完整初始化标签。
- 场景重试可复用已落盘的候选材料，不重做前置表演；旧 Studio 任务单接力适配器已从活跃运行时删去，Engine 的纯合同保留以免牵连其他入口。环境 Agent 的初始化与任务是两次实际模型请求，运行指标现如实计为两次。
- 演员沉默、无人参与或演员调用失败时，已生成的环境素材仍交给主创，不再因角色链路为空而废弃。没有环境也没有角色候选时才走原有降级路径。

规划窗口、条件式资产深化、场景准备、事实核验、独立审查、按证据修订和正式晋升各自拥有不同输入或责任；本轮未把它们当作“冗余”删除。字数续写仅在低于软下限时触发；一级言行审计在有角色候选时触发；主创主动索取素材才增加对应调用。现有 `max_actor_calls` 配置仍是场景参与人物数上限，属于既有成本偏好，未借这次审计提高或改变门槛。

场景之外也核过实际触发条件：长篇初始规划与后续章节窗口各自生成不同范围的计划，结构修复仅在校验失败时调用；人物背景只为仍等于生成占位稿的档案补全，人物语言声音在背景成形后集中创作一次，世界规则也仅在仍为生成占位稿时补全。它们不是每场重复运行的固定开销，直接合并会损失人物声音与背景因果的专门创作环节，因此此次保留。

## 验证范围

单元与集成替身覆盖开场合并、多轮公开言行、同一角色会话续演、环境补写、修订阶段请求、重试缓存、环境素材降级保留，以及实际模型请求计数。完整 Python 测试 1581 项通过、1 项跳过；末次补丁后的定向场景交互测试 12 项通过。Pi Worker 测试 109 项通过且构建成功；架构审计、模块地图与补丁空白检查通过。测试替身只证明编排和数据交接，不证明真实模型一定会主动请求素材或写出理想文风；后者需要隔离作品的正式场景试跑。
