# 缓存命中优化

2026-10-11。提高未变输入和合格结果的复用机会；模型、low/off 配置、文学 Gate 与知识分区保持。本批没有付费预热或额度探测。

## 服务端输入缓存

DeepSeek 官方文档说明，服务端自动保存可匹配的前缀单元，采用尽力命中策略；共同前缀更长不等于请求已经命中。实现只调整现有提示的排列，不增加缓存客户端或缓存保活调用。

新场景事务冻结 creator_prompt_layout=stable-prefix-v1。共同指导先出现，作者身份、文风来源、角色卡及稳定作用域随后出现，阶段指导与变化中的札记、目录、返修反馈放到后部。原上下文的所有值保留，数组及文学原文不排序或截断。角色设计合同时才提供完整设计指导；演员仍使用十一块完整卡。

已保存事务没有此布局标识时继续原布局，不因为这次优化重生成旧交付。未知布局保留错误，不能静默解释成已支持版本。已完成作品缓存保留。

## 本地结果与读取复用

materials/calls 的缓存身份按完整 JSON 值生成，忽略缩进、外围空白及对象键顺序；字符串内容、数组顺序、路径、知识分区和版本身份继续参与绑定。无效或重复键 JSON 仍按原始字节取键。

审读及返修先找新身份的结果，再计算当前输入对应的旧原始字节身份；只有准确匹配的旧结果且 DTO 解码成功，才迁移并保存来源回执。旧文件保留，不扫描相似结果、不放宽正文或合同绑定。

当前 Agent 内的资料回执同样忽略对象键顺序；跨调用重新交付完整内容。此回执减少重复上下文，不能算成服务端命中或模型调用消失。

记录整理缓存补入 material_need_contract，避免旧宽松上下文误命中新需求合同。可知卡片目标按集合表示；作品中的人物顺序和表演历史保持。

## 验证与费用口径

验证包括完整输入等价、共同前缀长度、旧布局冻结、JSON 排版命中、正文/历史/知识变化失效、旧结果零模型迁移及新调用原文交付。真实服务端命中率仍待余额恢复后的同阶段验收，402 不被标为通过。

旧轮输入共 13,847,527 token，缓存命中 11,165,055，命中比例约 80.6%。在旧轮非高峰价格快照、总输入及输出都保持不变的情景下，提高到 85% 或 90%，对应总费用约下降 6.6% 或 14.2%。这是条件计算，不能作为本批预测，也不能与先前流程节省估计相加。实际验收同时观察缓存 token、未缓存 token、总输入、输出及实扣；删除重复输入可能降低命中比例但仍减少费用。

依据：[DeepSeek Context Caching](https://api-docs.deepseek.com/guides/kv_cache/)，查询日期 2026-10-11；旧费用账本与非高峰价格快照沿用成本审计记录。
