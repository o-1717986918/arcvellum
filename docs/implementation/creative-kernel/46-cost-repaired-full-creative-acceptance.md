## 后置整理中的修复

本轮暴露的主要阻塞是原文已经生成而技术记录不合格。修复集中在 Studio runtimes 原文处理边界，Engine Gate 与角色合同没有放宽。

- 委托字段末尾标点发生技术替换时，只按唯一原文恢复实际字符；字词变化及歧义仍拒绝。
- 本地完整卡读取支持明确身份标签及其 Markdown 列表形式；人物提到另一个角色时，以自己声明的身份识别。字符串卡和未解码的事件文本产生可修复合同错误，不再以属性异常退出。
- 当取材库为空时，档案取舍留作创作札记；已返回的真实候选编号从材料目录读取，避免把旧记忆当成空库。
- 完成正文的明确标题或分隔段与旧委托回顾区分登记；“本轮重新委托”保留为等待素材的阶段，随附草案不直接晋升。
- 素材取舍共用前缀、省略编号及短哈希按原文位置证据恢复。短哈希须在实际候选目录唯一匹配；跨标题、碰撞、未知候选或散文数字不猜测。
- 作者回执明确引用沙盒札记时，读取其已经写好的札记并冻结路径和 SHA-256，原回执仍保存。冻结后文件修改不漂移到该次整理源。
- SceneDelta 整理上下文携带完整实际准入目录；技术修复任务合同仅列 repair_paths 对应字段，成功记录沿用。
- 同稿审读恢复引号、块引用等展示差异并保存原引文与正文位置。原审读者明确引用的内容确实不在当前正文时，退回原审读者；评语被整理器误放入 evidence 时仍按技术错误处理。判断、证据与问题编号分别校验。
- 验收日志允许空调用和时间预算，恢复运行时标记 running，成功推进后清除旧失败摘要。局部编辑以实际 system_prompt 归类；历史记录在报告副本中按实际发送提示重分阶段，不覆盖原账本。

这些变化保留原始文学文本及失败来源，不能代替创作者或审读者作文学判断。模块变更包、测试日志、真实调用及本轮交付在当前恢复工作区保存。
