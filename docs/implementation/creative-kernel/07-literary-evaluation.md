# 文学效果对照与盲评方案

程序验收只确认权限、状态和调用行为。文学效果需要在同一作品的现有场景上固定模型、温度、SceneBrief、来源、文风和角色人格，再比较四种主创提示：既有具体指导、加入开放文学意图、抽象主创扮演、抽象扮演加意图。角色人格化指引四组完全相同。另在同一主创提示下比较独写与主创按需调用描写器。

每组至少覆盖：安静日常场、关系误认场、多人冲突场、跨场景交接场。评审只看匿名成稿和已确认前文，不看组别与模型推演。记录人物辨识、有效留白、细节选择、趣味、误导是否有可回看线索、节奏、连续性，各项 1–5 分并写一条具体文本证据；评审还标记“无外部转折但成立”的场景，不用推进量替代文学质量。两名以上人评若分歧较大，讨论证据而非直接平均。

运行记录至少保存 `scene_id`、组别盲码、模型与参数、提示层 manifest digest、人物档案版本、工作意图、素材请求／取舍、成稿、成本与耗时。原文和私念只留在受控项目目录；评审表只用盲码。每组先用同场测试建立基线，再随机化组别顺序。通用 LLM 评委可用于指出遗漏的事实与视角越界，不能替代人评。

本次交付没有填写效果分数：2026-09-27 复核 `doctor` 时 Pi Worker 已报告 `ready`，但模型连接仍为 `configuration-required`／`probe-required`，提供者鉴权尚未证实，且尚未安排真人盲评。待连接验证与评审者就绪，再据此方案执行对照；不要把程序通过误报为文学效果提升。
