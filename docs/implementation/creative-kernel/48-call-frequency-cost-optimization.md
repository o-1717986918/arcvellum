# 模型调用频率与成本优化实施

实施日期：2026-10-11。模型保持 deepseek/deepseek-v4-flash。新事务采用按需取材、字段恢复和局部编辑候选；旧作品、原文、已完成交付和冻结提示继续保留。

## 调用与费用合同

- runtime/call_purpose.py 定义明确用途。正文、实质返修、取材、文学取舍及审读使用既有 low 设置；记录整理和已有判断的证据修复使用 off。
- role.invocation.started、runner.provider.request.started、runner.http.attempt.started 分别记录角色网关调用、逻辑模型轮次和 SDK 实际传输尝试。
- Pi 通过 SDK 的 fetch 扩展观察重试。观察器返回原 Response，不读取请求正文、凭据、URL 或响应流。
- runtime/usage_accounting.py 是 Creative Live 和验收账本的共同费用口径。用量按身份去重；目录 USD 估算、带查询日期的公开价格 CNY 估算、独立实扣记录分别保留。
- 思考 token 已包含在输出计费中。缺失用量、缺失目录费用和无响应调用分别显示未知；HTTP 未被观察到时返回未知。
- 公开价格使用 2026-10-11 快照，价格时点优先取可观测 HTTP 起点。节假日时段及供应商实际结算未核验，估算不等于实扣。
- Live 的会计事件保留独立于 800 条展示队列；API 对持久事件分页读取。客户端保留完整用量身份，240 条显示窗口淘汰事件后不会重复累计。

## 保存、恢复与字段补交

- 所有自然输出统一进入 NaturalTransportPipeline。旧缓存先在当前上下文重新校验；不能证明兼容的记录继续作为历史证据保存。
- 原文、正文、SceneDelta、委托和取舍分别保存检查点。正文检查点只证明原文一致，不能替代文学 Gate。
- 恢复身份绑定原文、语义上下文、提示和输出合同以及处理器版本。同一失败身份不变时先执行本地检查，再保留阻断，不重复付费。
- 已存在成功字段和成功整理优先复用。未知失败没有整份主创补全权限。
- 原作者补交采用指定 JSON 路径。允许修复 SceneDelta、证据、知识分区和卡片字段；正文及已有审读判断保持冻结。
- 原引文确实不存在时，由原审读者以 low 核对具体失败项，可在授权路径内更正或撤回该项，并更新结论；其余判断冻结。格式及编号问题沿用已有判断，使用 off。
- 纯字段补交没有创作工具；文学素材取舍只可读取当前事务候选。取舍补交不再携带整份创作指导和档案工具。
- 审读和返修缓存使用正文、任务、必要来源、文风快照和审读连续性。思考降档不会使完成输出失效。返修完成后保存其新增素材对应的恢复身份。
- 新审读原文采用正文与上下文双重身份保存，追加历史；旧审读原文件不覆盖。

## 素材与人物历史

- 新委托提示要求说明文学缺口、已有材料为什么不足及预期正文位置或组织用途。咨询组合由文学需要决定。
- delegation v11 增加 need_evidence；首次委托说明观察必要性，后续引用已检查候选的准确原句，每项 archive/material 挂载逐项给出主创理由。整理器核对其原文来源，执行层核对候选与挂载清单；缺依据时只补指定元数据，未核对前不发起取材。
- 需求依据绑定主创原文及判断当时的候选版本。同批独立邀请共享调度前资料快照，之后生成的候选不会错误阻断该批余下邀请。历史合同不被强行升级。
- material_input_reuse 绑定实际系统、委托、来源与知识分区、角色历史、响应合同；仅修改记账依据而实际输入相同时复用原回应，复用记录另存，不重复计为实际调用。
- 主创上下文只交付一份内容完全相同的冻结/作品角色卡，另一位置保留目标、来源与身份回执；不同版本全部保留。札记不重复已有编号列表。
- 候选读取只省略与外层相同的元数据。长对白、动作及私人冲动若在完整原文中唯一出现且位置记录更短，可用 UTF-16 位置表达；歧义、短字段及不同内容继续原样提供。原文及磁盘源记录保持完整。
- 后续邀请先读已有回应，提供新刺激、未解决问题和相关片段。没有新增摘要模型。
- 档案增加批量读取。当前 Agent 上下文已收到相同版本和范围时返回来源回执；下一次调用重新提供原文。
- 同一委托的档案及候选重叠范围合并，保留原始选择器、来源和范围。角色 known/reference 分区分别合并，跨分区不合并。
- 演员继续使用完整十一块角色卡；主创在设计或更新时加载完整设计合同。
- 取舍历史不再截为 40 条，理由不截为 240 字符。当前投影采用每个候选最后一条决定。
- use/adapt 可登记来源片段、正文原句、位置和间接用途，程序核对字面锚点。缺证据、待后续使用 defer 和明确舍弃 discard 分别显示。
- 演员历史纳入 use/adapt，后来舍弃的候选退出。adapt 的原文和正文落点作为有来源的参考；亲历、听闻和可知事实由本轮来话及 known 档案界定。仅用于结构理解的素材不冒充实际经历。
- 采用比例和字面复用比例不能代表真实文学利用率。

## 编辑

- 新挂载采用 focused-candidates。只有原主创或审读者明确提出 editor_focus 才发起局部编辑。
- 编辑输入包含问题、对应段落与必要背景。词义、人物声音和世界设定等建议保持候选，进入已必要的原主创返修。
- 无实质返修时保留原稿，不为采纳建议另开整篇创作循环。
- 明确请求的段末空格清理在本地完成，保留段落、对白、数字、人物名与交接证据；原稿和格式处理记录保留。
- “攒姓→攒盘缠”回归验证证明建议不能自动改变奇幻词义。

## 验证与交付边界

验证覆盖恢复、字段权限、知识分区、取舍投影、缓存失效、SDK 重试/402/流式中断、费用去重和双端组件显示。架构审计不放宽既有基线，模块地图及提示注册表同步。

旧真实实测的 69 份独立原文输入离线回放：61 份恢复，8 份保留具体阻断，新增项目模型调用为 0。这是记录恢复验证，不是新一轮文学质量验收。

四个 call-cost-optimized-v4 隔离项目已准备。已知供应商 402 保留为断点，不探测余额或自动重试。真实付费验收未运行，因此没有新的实际费用或全流程节省百分比。

资料结构离线回放：82 个候选文件在相同紧凑 JSON 口径下减少 19,988 字符，12 个字段可由精确位置还原，原文不变；24 份主创上下文移除重复卡与编号后减少 77,464 字符。两组口径不同，不相加，也不是净 token 或费用节省。

新指导增加 596 字符/主创调用，测试夹具的无挂载需求记录为 189 字符/委托；实际需求记录和内部回合重复输入尚未实测。成本论证计入这些额外输入、缓存命中变化及输出，不能只按删除字符计算收益。记录完整性可确定性验证，文学必要性与实际收益仍需原主创判断及真实审读。

本次交付包含源码、Pi Worker 构建、桌面 Worker 资源及前端资源；已安装桌面侧的 Python sidecar 和安装包尚未重打包，运行中的服务未替换。源码开发服务重新启动可加载源码变更，发行版需要重新构建 sidecar/安装包。共享工作树的原有修改不纳入独立提交；回滚以本轮开始时的快照及本轮增量补丁为单位。
