# 创作缓存、连续性与参照来源审计

2026-10-12。用户授权分析缓存、Canon 读取与写回、文风参照集中和取材浪费，并切换测试到 Discovery 接口。正式正文、历史取材与审批状态保持原样。

## 本批范围

主模块分两批：Pi Worker 的既有 SDK 模型目录配置；Studio runtimes 的上下文交付与来源记录。Module Change Packet 和修改前逐文件快照保存在接续会话 `work/creation-optimization-module-packets.json` 与 `work/creation-optimization-before/`。共享工作树的其他历史修改不纳入本批。

## 缓存

历史八单元混合版本账本的输入 token 命中比例为 65.90%。主创生成 84.39%，返修 84.54%；文风选择 4.71%，取材 20.89%，记录整理 22.64%，审读 33.26%，局部编辑 33.75%。这些是已记录命中 token 除以命中及未命中输入 token 的分阶段比例，不是请求成功率，也不是当前稳定版本的单一基准。

文风选择将完整参照目录置于场景变化信息之前。记录整理保持冻结 context 在原文之前，原文与 source_index 在变化中的 task_contract、剩余字段及反馈之前。来源字段值、原文、数组次序和知识分区不变，不新增缓存保活或额外填充内容。取舍指导另明确支持 defer。

237 份历史整理提示中，有 73 对相邻同源请求可比较。在同一 system、operation 与 source_text 分组内，序列化用户提示的共享前缀中位数从 48 字符增加到 22,794 字符，55 对增加。该回放仅证明结构上的命中机会，不等于服务端实际命中率提高。

新事务冻结 runtime_model_binding，包含各角色的运行时、模型和所选自定义模型的请求相关定义。中途换模型或端点时明确拒绝继续该新事务，要求建立独立事务。价格和显示名称不参与此身份；凭据不被读取或写入身份。旧冻结事务不被静默迁移。

Qwen 实测出现人物卡标题明确、CORE_IDENTITY 只有独立代号的情况。旧解析误把代号当姓名而无法恢复完整卡。新解析只在完整块集合、唯一身份原文和明确已知卡标题一致时恢复；冲突或重复仍拒绝。原回答中的两张 11 块卡本地恢复成功，所有块原文保持，新增模型调用零次。

同一原回答的 creative_intent 被整理成四份同一长段，触发原生字段限额。新验证在读入记忆前调用 Engine public CreativeIntentV1 验证；超限或格式错误经既有原作者指定字段补交协议恢复，仅授权 /creative_intent。其余内容冻结，600/400 字符限制保持。明确空更新的历史兼容行为保持。

无效取材计划通过 /material_plan 交原主创定点选择，不由程序决定伙伴；把 creator_scratch 笔记当作品档案时，仅授权对应委托的 archive_attachments、working_context、need_evidence 更正，原读取边界保持。记录整理提示说明根来源摘要无需模型返回，由既有解码器绑定当前保存原文；若明示错误摘要或原文引用对象仍拒绝。技术整理版本升至 cost-recovery-v4.37，保留旧失败记录，优先恢复已有效交付。

## Canon 与前文

已有 AtomicProjectSceneCommitter 将正文、SceneDelta、连续性、Canon 候选、时间线和回执原子写入。已确认事实与 pending_confirmation 候选分开保存；模型在札记中写“确认入 Canon”不会自动产生审批或应用回执。

本轮历史问题主要发生在事实覆盖与读入：世界第一单元建立大量风俗却未记录 Canon/连续性提议；群像组记录格言而没有充分记录桥的数量和空间；主创 starter packet 只直接提供上一正文尾部，Canon facts 与 timeline 主要作为按需路径；较长 Delta 与连续性又被节选。

新生成的 starter packet 完整提供上一正文、上一 Delta、连续性投射以及场景引用的 Canon 文件，明确候选、传言与已提交叙述的状态区别。旧已冻结 briefing 保持。新增交付指导要求清点数量、方位、人物经历、习惯来历和未兑现条件，覆盖 SceneDelta 或说明无变更理由。非角色的肖像、事件及环境邀请明确区分新设想与来源事实。角色的 known/reference 选择仍由主创负责，未把导演秘密自动交给演员。

这是完整读取与来源指导的改进，不是对模型语义完整性的保证，也没有自动晋升 Canon 或改变正式审批 Gate。

## 文风与材料

实际选入的参照文字约 80.33% 来自《镜花缘》和《老残游记》，两书样段合计 49/97 次参照选择。目录还有 25 个用户样段，但其作品来源没有完整标识，不能把样段数当作独立作品数。

文风选择展示来源样段数与字符量，并要求按表达功能判断独有用途；样段较长或较多不构成全部采用的理由。不删除原参照，不强制配额，不下载或伪造其他作品样段。

48 次取材生成 104,652 字符，形成 124 个候选；最终有 115 条选择记录，9 个候选未登记。采用/改写 102 条、留待后文 7 条、舍下 6 条。最终稿上重查：双引文锚点通过 4 条，间接用途描述 23 条，未登记锚点 63 条，引文锚点未通过 25 条。上述标签和字面锚点均不能充当真实文学利用率或浪费率。

完成正文时新增按正文 hash 保存的 material-usage 审计，复核继承决定在当前正文中的引文，保留原文学选择和原始记录。补取舍时保留来源片段、正文落点与间接用途，明确支持 defer，不为补编号要求所有材料强行用完。

## 新接口与验证

使用用户提供的 Discovery Base URL，通过既有 Pi SDK 的 openai-completions 实现加载用户 Agent 目录 models.json；认证仍由 ReadOnlyJsonCredentialStore 读取，工作项目不保存密钥。没有新增 HTTP 模型客户端或隐藏回退。配置文件支持新增目录项，保留原 built-in 模型；不允许自定义项静默覆盖 built-in 供应商。

Intern S2 两次真实短回应成功，分别耗时 47.85 秒和 124.98 秒；归一化用量未报缓存命中。随后人格初始化 180 秒超时，失败记录保留。GLM-5.3 的人格与主创生成成功，主创过程报告正值缓存读取；技术整理的原生 ZAI 关闭思考配置返回 HTTP 400。该观察不证明 GLM-5.3 在此端点完全不支持关闭思考。

最终测试模型为 intern-discovery/qwen3.8-27b。low 测试使用独立 discovery-qwen-test-config.json 与 canon-cache-qwen-v6 variant；其主创最后一轮输出 32,768 token、推理同为 32,768，没有最终正文。旧执行器 lastAssistantText 回溯返回了较早的中间说明而误报完成，后续整理才报失败。新完成判定检查最后一条 SDK assistant 的 stopReason；length、未完成 toolUse、error 和 aborted 均保持阻塞，不以中间说明冒充完成。新增独立 discovery-qwen-off-test-config.json 与 canon-cache-qwen-off-v7 variant，主创及伙伴也关闭思考，原失败记录保留。

只切换隔离测试，全局模型配置保持。连续场景人格沿用已保存的 GLM-5.3 原作者人格，作为固定输入，不能声称 Qwen 完成人格到全文的独立验收。

重放同一保存的技术整理请求：SDK 原平面关闭方式仍产生 19,462 推理 token、耗时 124.83 秒；使用 SDK 原生 compat.thinkingFormat=chat-template 与 chatTemplateKwargs 的 enable_thinking=$var:thinking.enabled 后，耗时 18.55 秒、推理 token 为零。输出与请求完整保存。这只验证本次技术思考开关生效，不是整体提速、缓存命中提升或字段语义验证通过的证据。未增加自定义请求参数转换器；主创 low 不构成硬推理 token 上限。

连续重放两次相同真实技术请求，耗时 24.16 秒和 14.42 秒，均报告输入 6,950、推理与缓存读取零。新接口实测仍未证明缓存命中改善，不据此推断后端没有缓存实现。
