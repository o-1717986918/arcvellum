# 描写器与按需取材设计

角色表演的人格化初始化继续是文学能力。人设稳定身份、内在反差和语言气质在初始化；当下关系压力、可知信息和回应对象在逐轮任务。描写器不替代角色表演：人物描写器只写可观察呈现，事物描写器关注质地与使用痕迹，场面描写器为空间中已发生的言行取景，环境 agent 负责空间氛围。只有主创提出有文学目的的请求时才运行。

`MaterialRequestV2(kind,target,purpose,scene_moment,cue,beat_id?,scene_change?)` 将效果与时刻交给描写器。三类描写初始化持久保留职责、作品表达与观察方式；每次任务给 SceneBrief 的视角、场所、参与者、已确认来源和公开舞台。候选为零至三段，可说明此刻应保持空白；程序限制条数和篇幅。场面描写不代演员发起关键行动，人物描写不宣称视角外私念，所有候选不进入 Canon 或正式正文。主创二次选择后可以采用、改写或舍弃，理由放在场景工作记忆。

调用流：主创首次回应 `creative_intent` 和写作/取材选择；Studio 仅在取材时执行候选 agent。角色通过现有 `actor-conversation/v2` 保持历史。环境与描写器通过 `role-conversation/v1` 保存有界历史；Pi Worker 仍以 `tools: []` 运行。请求失败不伪造候选，留给主创修订请求或直接成稿。

纯描写请求直接建立描写会话，不先生成整套角色表演规划。后来如请求角色，才生成规划、初始化角色，并在原场景候选状态中继续；环境重复请求续接同一环境历史。单批请求按提示摘要和序号标记，重启时跳过已落盘的角色、环境或描写结果。

初步验收：比较同场主创独写与按需取材，固定角色人格与模型。盲评细节是否被选择、是否增加人物辨识或有效留白，以及候选是否使主创机械照抄；程序检查来源和写权边界。
