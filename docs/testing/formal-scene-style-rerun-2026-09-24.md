## 与原场景的可观察对照

原项目既有正稿约 2473 个中文内容字符；本轮二次候选为 2903。以“。！？ ”粗分句子，原稿 119 句中约 61 句不超过 14 字，中位句长 14；本轮 127 句中约 45 句不超过 14 字，中位句长 21。这个粗统计只说明短句密度下降，不能单独证明文学质量提高。

原稿的精确时间、航线编号与分钟数反复出现，功能性问答密集。新稿避开这类装饰性读数，让雨、广播、人流、巡逻灯分别作用于遮蔽、暴露、断线和直连，场景因果更清楚；“烤栗子”和“加急价”的回弹也让许遥稍有个人语气。代价是人物仍主要靠职业立场说话：周岑用技术流程回避，许遥以玩笑催促，缺乏更稳定、只有他们会使用的词域和句法。隔离槽—断线—开终端—锁定的动作链很完整，但有些段落仍像有序的操作步骤。对姐姐的记忆和两人不说破的关系，心理时间给得少，许多情绪靠物件或末尾意象代理。

首稿还出现三类“意义已经成立却又解释一遍”的尾句：解释许遥说“锁死”如何让周岑松手、解释她重试卡扣后周岑发现自己屏气、解释“天亮”说得平常意味着什么。二次候选已针对这些准确位置局部改写，保留行动链而不做批量删句。尚需独立读者判断改写是否真正更有余味。

另一个连续性警报：原项目既有正稿把许遥写作“他”，这轮隔离副本的新候选写作“她”；正式人物 YAML 没有性别或自称字段。因为测试副本没有把原正稿当成当前场景的来源，形式上的场景上下文没有发现漂移。这说明人物事实不够完整，并非单纯文风问题。二次候选不得直接替换原正稿。

## 问题来源，不是门禁数量

1. 当前挂载风格名为 `arcvellum-clear-plain-prose`，明确偏向“清楚、流畅、朴素”、过场压缩与低修辞。场景合同又设 `reflection=low`、`description=low`，要求段段承担功能。两者叠加，容易让文字过分节省情绪与环境的停留时间。生成标准虽要求长短句随压力变化，但场景的局部约束更具体。
2. 正式人物资产只有短背景与欲望，未填 `speech_style` 等稳定声线信息；构成文件里两人的 `stable_voice.vocabulary/rhythm` 为空，`speech_strategy` 完全相同，均为“让语气服务关系压力，少解释，多留白”。主创只能临场依据职业刻板差异猜声音。
3. 生成 prompt pack 的 `style_reference_selection.status=legacy-unindexed`、`references=[]`。挂载风格文本确实进入长达约 7.2 万字符的 user 消息，不能说参考语料完全缺席；但没有本场选中的示例及可检查的取法，语料影响可能被总体任务文本稀释。
4. 这条正式 CLI 路线只运行了角色的行动/分支推演，**没有运行独立角色台词与动作素材 agent，也没有运行独立环境描写 agent**。相关代码位于 Pi 场景运行时 `runtimes/scene_performance.py`，而非本次 `generate-scene` 的正式 prompt pack；本机应用配置读到 `scene_performance_agents.enabled=false`。所以本轮不能拿来证明该多 agent 文风机制有效或无效。
5. 首次构成审查虽通过，却没有识别场景桥接与章节义务的结果冲突；直到正文审查才暴露，造成重跑。应在规划资料之间消除矛盾，而不是给语言审查增加门禁。

## 下一轮应如何验证

先在隔离配置中实际启用 Pi 场景素材链，保存角色 agent 的整场发言/动作、环境 agent 的段落和主创最终正文；对照同一场景合同做一次未启用素材链的基线。比较人物声线、情绪停留、短动作清单、解释性尾句与环境因果，而不只比较字数或 lint 命中率。人物底线和场景目的保持明确，但角色语言应留足个性化自主性；环境素材应允许停留与气氛，不把每句都押在即时推进上。软审美问题优先在生成任务单和风格提示中解决，违禁词及标点仍由审查处理。正式晋升前还需补齐独立审查与状态写回。
