## 2. GitHub Issue #20 归因

Issue 截图暴露的是跨模块产品故障，不是一条错误文案：

| 现象 | 责任模块 | 必须修复的根因 |

| Prompt `67021 > 48000` | Prompt Program / Evidence Projection | 编译前预算、按任务裁剪和可行动的超限诊断 |
| `repair timeout` | Runtime Provider Reliability / Repair | 独立 repair timeout、错误分类和有限恢复 |

内部异常原文保留在诊断日志和高级观测中；普通界面只展示稳定错误代码、中文说明和可执行动作。

## 6. E2b 批次计划：Pi Worker 多产物落地协议

真实基线在 `character-and-world-assets-world-foundation-asset-review-pass` 暴露了一个可复现的运行时协议缺陷：模型已经提交四个 Agent-owned 产物，但首轮超长批量工具参数被 Provider 截断，其中世界规则 JSON 留下语法错误；随后模型在同一响应中逐文件调用四次 `validate_output`，首个校验改变了全局协议阶段，导致其余三个兄弟调用被错误拒绝，并在第六轮耗尽预算。

本批按 Runtime 模块边界修复，不增加轮次来掩盖问题：

1. `write_expected_output` 每次写入后自动运行全量本地校验，并把聚合错误返回模型；
2. `validate_output(path)` 可以返回单文件结果，但 Worker 的内部状态始终保留全量聚合结果，避免最后一个通过的单文件覆盖其他失败；
3. 一次 Provider 响应开始时冻结该响应的 required-tool lease，同一响应中的兄弟工具调用不因前一调用改变状态而被误拒绝；
4. 多产物写入提示明确限制超长 batch，优先按一个完整产物一次提交，避免工具参数在 Token 上限处被截断；
5. 增加“截断 JSON + 多文件 + 最后一轮修复”的 Worker 回归测试，再恢复真实 E2E 基线验证。

完成标准：相同四产物任务在一个 JSON 语法错误时得到精确修复机会；无效兄弟调用不消耗为协议冲突；全部产物本地有效后仍由 Studio 正式预检裁决。

### E2b 实施记录（2026-08-20）

- 写入工具现在立即返回全量聚合校验，截断 JSON、缺失兄弟产物和提交来源问题都能在同一轮被模型看到；
- 单文件 `validate_output` 不再用局部通过结果覆盖全局失败状态；
- required-tool 改为 Provider 响应级 lease，同一响应中的兄弟调用不会因先执行调用改变状态而被误判为越权；
- 主创 Worker 取消“所有产物必须首轮批量提交”的危险指令，超过 12000 字符的多产物任务按完整文件逐项提交；
- Pi Worker 46 项测试、Python Runtime/合同 24 项测试及架构审计通过，未增加依赖违规或循环。
