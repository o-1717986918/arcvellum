# 文风优化基线与盲评规程（2026-09-23）

基线为 v0.99.10 / `ab8dd08` 的《潮痕之下》五章正式场景，来源见 [前次长篇验收](top-agent-100k-five-chapter-e2e-2026-09-22.md)。该运行完成 35 场、92,348 个中文内容字符，工程闭环成立，但相邻场景重复、人物称谓碰撞、后半程字数不足与平铺语言均已记录；不可把它称为文风合格成稿。

八类固定场景与四组邻场见 `benchmarks/prose_style_cases.json`；八篇基线正文的相对路径、SHA-256 与长度见 `benchmarks/baselines/prose-style-v09910/baseline.json`。仓库不复制用户整本作品。运行 `python -m benchmarks.prose_style_ab --baseline-project <作品目录> --output-dir <输出目录>` 会验证并重新生成基线记录；提供 `--candidate-root` 时，要求 B—E 各场正文和对应 Prompt Manifest，生成随机顺序的盲评包及单独揭盲密钥。脚本不调用模型、不改动作品。

固定规则文本基线（字符，含模板占位符）：route asset 3,954；system template 1,106；user template 604。当前改动后分别约为 2,056、274、749。模板长度不是最终 Prompt 长度；后者必须在同一场景包、相同挂载与 Runtime 上比较，并单独记录所选完整参考及实际被截断的来源。

## A—E 消融定义

- A：v0.99.10 已完成正文；只用作历史基线，不伪装为相同随机种子重新采样。
- B：移除固定正文种子和无依据感官填充，启用表达计划。
- C：B 加入按场景选中的完整参考。
- D：C 加入稳定声音与当下声音。
- E：D 加入软/硬审读分工和最小返修。

比较时使用同一 scene、Canon、人物、模型版本与 Runtime，并记载温度/思考强度的实际能力和设置。A 来自历史运行，因此结果只能证明候选相对历史成稿的读者偏好，不能独立归因为单个组件；B—E 之间的比较用于定位增益。模型随机性、上下文版本和候选字数均需进入评审记录。

## 盲评与放行

至少三位读者独立评价总体继续阅读意愿、语言速度变化、去名人物辨认、修辞来源、证据后解释、重复收尾和连续措辞风险；必须引用具体句段。每场先选首选版本，再按七项维度评分，不先看揭盲密钥。四组邻场另查动作链、首次事件、悬念收尾是否重复。自动 lint、相似度和 n-gram 只用于定位退化，不能代替人类偏好。

当前状态：基线文本哈希与评测工具已准备；B—E 的同题候选、三读者盲评和新版本五章约十万字 E2E 尚未取得。发布验收线仍以开发计划第 5.4 节为准，不能把现有单元测试通过写成文学质量通过。

采样温度未作为本批可调项：当前生产 Runtime 只公开思考强度，没有可核验的采样能力与生效值；界面不会提供名存实亡的温度滑块。待 adapter 报告该能力后，再按 Runtime 分开做稳定／均衡／活跃预设试验。

## 三场景验收补充：资产深化阻断

新建隔离作品《岸外来信·文风样本》以完成三场短样。顶层 Agent 已生成一章三场的规划，资产深化却在 `character-and-world-assets` 停止。单人物任务单指定只深化沈照月，真实 Pi Worker 回复仍包含沈照月、周鹤、叶归舟三人；Studio 的全量名单校验将这份结果退回，结构返修仍发生同类错误。生成内容不得越权写入其他人物资产，但也不应让无关的额外条目阻断已请求人物的有效结果。

```yaml
module_change_packet:
  objective: "单人物资产深化只采纳所请求角色，模型额外返回角色时不阻断三场景测试"
  primary_module: "Studio application/lean_asset_enrichment.py"
  public_entry: "enrich_lean_planning_assets(project_root, gateway)"
  variation_point: "单人物模型回复的无关角色条目隔离"
  inputs: ["已规划人物", "仍与生成 stub 完全相同的人物 YAML", "Pi Worker JSON 回复"]
  outputs: ["仅请求人物的背景深化", "已有 world rules 的独立深化"]
  invariants: ["绝不写入未请求角色", "请求角色缺失或重复仍失败", "用户编辑资产不覆盖", "不放宽世界规则验证"]
  allowed_dependencies: ["现有 lean_assets stub", "RoleConversationGateway", "项目原子写接口"]
  forbidden_dependencies: ["Engine 内部文学模块", "API/前端", "额外返回角色的正式写回"]
  tests: ["额外角色被隔离", "请求角色缺失或重复失败", "原有资产测试", "三场真实创作"]
  rollback_unit: "资产深化适配器单独提交"
  documentation: ["本验收记录"]
```

## 三场实际创作结果与未通过项

隔离作品位置：`build/prose-style-e2e/projects/shoreline-style-smoke`。顶层 Agent 完成一章三场规划；修复资产深化适配后，三个人物背景与世界规则均生成。`scene_0001`、`scene_0002` 已通过现有流程进入 `drafts/scenes/`；`scene_0003` 完成生成、两轮返修及审读，但停在既有的高风险场景人工批准点，候选保存在本机数据目录的 scene transaction 中，未冒充正式晋升正文。本轮没有导出或发布。

这次运行能证明参考投射事件和真实 Prompt 的存在，不能证明成文质量提升。旧不可变文风版本在本次项目创建时已挂载，实际选段为第一场 R04/R23、第二场 R23、第三场 R23。检查第二场约三万字符的真实 Scene Create Prompt，`Relevant Sources` 约二万一千字符，而 `Style Reference Priority` 只有约二百五十字符，且 R23 是密闭恐惧的样本，却因章级“控制室／广播”进入证人日常对话。针对这个实际失败，已限制 lean 选择上下文为本场事实，移除 R23 的泛化媒介词；新索引只应用于**新建文风版本**，不改写这次作品已冻结的版本。因此这组三场不能作为“修正后选段必然有效”的实证。

读稿未达到文学放行标准。第一场大量登记簿、绳结、设备步骤构成连续流水账；“九点十分”“半尺”“三圈”“半秒”等精确值仍有多处装饰性实写。第二场人物声线可初步辨认，但沈照月、周鹤共用程序/档案/签名栏词域，问答主要用于说明手续，差异更多来自职业标签而非各自欲望与关系；下颌、铅笔、纸张、茶杯的小动作反复出现。第三场候选仍以设备核对和记录解释为主。第二场周鹤说“三十年了”，与规划里“停播十年”的事实明显不合，也提醒我们不能用风格通过掩盖连续性失败。人类盲评仍未进行，不能宣称文风优化成功。

另有一个跨层诱因：当前新场景模板固定写着“每段至少承担行动推进、信息改变、关系压力、选择代价或场景衔接之一”，三场的 `description_ratio` 均为 `low`。它可能把可供审美停留的感知、幽默、节奏变化挤成纯功能段落；这是由本次 Prompt/成稿对照得出的工程假设，尚未做单变量消融。后续计划应把该默认值与角色表演任务单一起比较，不应直接扩大审查门禁。
