# ArcVellum 星仪性能与桌面渲染优化计划

## 1. 目标

在保留星仪完整作品脉络、关系证据、交互窗口和沉浸式视觉的前提下，降低首屏等待、持续动画、摄像机移动和桌面 WebView 合成成本。性能降级只能减少装饰性计算，不能删除作品事实、关系语义或正式功能。

## 2. 当前实测基线

测试对象为当前开发构建中的《兄弟》项目，视口为 1600 x 900，设备像素比为 1.5。

| 指标 | 完整动效 | 克制动效 |
| --- | ---: | ---: |
| 平均帧耗时 | 40.9 ms | 11.3 ms |
| P95 帧耗时 | 60.6 ms | 18.2 ms |
| 近似帧率 | 24 FPS | 55 FPS |
| 同时运行的动画 | 305 | 100 |
| 星仪节点按钮 | 116 | 116 |
| SVG 路径 | 583 | 583 |
| 页面 DOM 元素 | 2330 | 2330 |

完整动效下关闭所有 CSS 动画后，P95 帧耗时回落到约 30.2 ms。这说明关系线和节点 CSS 动画是第一层热点，持续锚点投影与 Vue/SVG 更新是第二层热点。

首屏网络与解析基线：

| 读取面 | 响应体 | 实测耗时 |
| --- | ---: | ---: |
| 创作现场快照 | 约 442 KB | 约 1.03 s |
| 项目工作区快照 | 约 288 KB | 约 0.97 s |
| 星仪投影 | 约 449 KB | 约 0.26 s |

首屏脚本传输约 1.06 MB。`OrreryWorkbench` 构建块约 509 KB，主入口构建块约 303 KB。页面同时存在约 27 个 `backdrop-filter` 合成元素。

## 3. 根因

### 3.1 全场关系线持续动画

章节辐条、证据关系、人物关系与创作阶段路径同时执行虚线位移动画。当前样本中约有 205 条 SVG 路径持续动画。关系必须常驻可见，但没有必要全部持续运动。

### 3.2 摄像机循环驱动全量响应式更新

`NarrativeParallaxRenderer.tick()` 每帧更新天幕、视差和关系 LOD。只要投影中存在可漂移节点，渲染器就按约 42 ms 的间隔重新计算全部屏幕锚点。新的锚点对象会继续触发：

- 节点位置和标签避让重算；
- 章节重心和章节辐条重算；
- 证据、人物与场景关系路径重算；
- 小地图可视框与离屏信标重算；
- Vue 虚拟 DOM 与 SVG 属性更新。

轻微节点漂移由此升级为整张图的持续重排。

### 3.3 动效等级未完全贯彻

克制动效下仍有约 100 个节点呼吸动画。部分 `available`、`active` 和生命周期选择器只服从系统级 `prefers-reduced-motion`，没有完整服从 ArcVellum 自身的动效等级。

### 3.4 全屏天幕持续以高像素密度重绘

程序化天幕每帧计算多层星点、云团和 FBM 噪声。自动质量把分辨率上限设为设备像素比 1.5，高 DPI 桌面屏会显著增加片元着色量。Pixi ticker 在场景静止时仍保持运行。

### 3.5 首屏装载了非首帧必需的完整资料

星仪信标只需要创作状态摘要，但当前会立即连接完整创作现场；工作区快照也携带档案、阅读和观测信息。三个大型 JSON 在进入首页时并行读取、解析和写入状态。

### 3.6 桌面端承担额外合成压力

Tauri 配置没有关闭 GPU 加速。桌面端表现更差主要来自 WebView2 同时合成高 DPI WebGL 天幕、大量 SVG 动画、DOM 节点、阴影和磨砂层。当前证据不支持更换前端框架或改写原生渲染层。

## 4. 实施路线

## P0：动画预算与立即止卡

1. 增加统一的动效预算：同一时刻只允许当前任务、实时生成链路、选中节点和选中关系运动，目标上限为 20 至 30 个动画对象。
2. 其他章节、证据、伏笔、人物关系保持清晰静态；视觉降级不删除任何关系。
3. 修复克制和静止模式下残留的节点生命周期动画。
4. 页面不可见、窗口最小化或星仪离开前台时暂停 Pixi ticker 和装饰动画。
5. 桌面自动质量将画布分辨率上限调整为 1.25；性能优先保持 1.0。
6. 天幕空闲刷新率限制为 20 至 30 FPS，摄像机交互期间允许短时提升。

临时用户策略：在“设置 -> 场域与动效”选择“克制动效”和“性能优先”。当前实测可把 P95 从约 60.6 ms 降到约 18.2 ms。

## P1：渲染循环收敛

1. 为摄像机、构型、投影、主题和尺寸分别建立 dirty flag。
2. 只有摄像机矩阵或投影几何真正变化时才发布锚点。
3. 将轻微环境漂移改为局部 CSS/GPU 动画，禁止它触发全量锚点发布。
4. 小地图、离屏信标和标签避让限制为每秒 8 至 10 次更新，并在摄像机静止后补一次精确结果。
5. 将关系线迁移到 Pixi 世界坐标批绘制，或让 SVG 关系层共享单一摄像机矩阵。避免每帧重新生成数百个路径字符串。
6. 将正文窗口、档案窗口和工具窗口的更新与星仪摄像机帧解耦。

## P2：数据和首屏拆分

1. 新增轻量创作现场摘要接口，只向首页信标提供状态、当前任务和活跃节点。
2. 打开创作现场窗口后再加载完整会话、产物、审查和事件历史。
3. 将工作区快照拆分为首页摘要与按窗口加载的档案、正文、交付、观测数据。
4. 精简星仪投影，只保留布局、标签、状态和关系所需字段；详细内容继续通过节点详情接口读取。
5. 按投影修订号缓存布局与关系几何。非结构事件不能重建布局。
6. 将星仪构建块拆为核心场景、导航探索、空间窗口和创作现场四个异步边界。
7. 生产发布关闭 source map；该项主要降低安装包体积和同步成本，不作为运行时性能收益计算。

## P3：自适应性能治理

新增独立 `OrreryPerformanceGovernor`，由它统一决定：

- 天幕刷新率和像素密度；
- 关系线细节与动画数量；
- 节点环境运动数量；
- 标签预算和小地图刷新频率；
- 完整、平衡、性能三档运行策略。

治理器根据 P95 帧耗时、节点数、边数、DPR、页面可见性和桌面环境动态调整。降级过程保留数据和交互能力，交互结束后按稳定窗口逐级恢复，避免频繁抖动。

## 5. 模块边界

| 模块 | 责任 |
| --- | --- |
| `engine/parallaxRenderer` | 帧循环、摄像机 dirty state、ticker 生命周期 |
| `engine/sky` | 天幕质量、降采样、刷新节奏 |
| `engine/relationRenderer` | 世界坐标关系批绘制与关系 LOD |
| `OrreryNodeOverlay` | 可交互节点和标签预算 |
| `NarrativeSpineLayer` | 章节脉络语义与必要的高亮关系 |
| `OrreryNavigationLayer` | 小地图、搜索和离屏导航的低频刷新 |
| `services/orreryPreferences` | 用户显式体验偏好 |
| `OrreryPerformanceGovernor` | 环境测量和自动性能预算，不持有作品语义 |
| Studio projection API | 紧凑投影、摘要接口、修订和增量补丁 |

性能判断不能分散为大量组件内的临时条件。组件声明自己的视觉能力，由治理器下发预算。

## 6. 验收标准

以《兄弟》及规模不小于 136 节点、352 关系的固定项目验收：

- 桌面冷启动后星仪可交互时间小于 3 秒；
- Web 热启动星仪可交互时间小于 1.5 秒；
- 平衡档空闲 P95 帧耗时小于 20 ms；
- 平移、缩放和视角调整 P95 帧耗时小于 25 ms；
- 稳定后不存在超过 100 ms 的主线程长任务；
- 同时运行的 CSS/Web Animation 数量不超过 30；
- 首页首批业务 JSON 总量控制在 300 KB 以内；
- 所有正式章节、场景、人物、证据、伏笔和审查关系仍可见、可搜索、可聚焦；
- 高亮、实时生成和镜头过渡保持明确的视觉反馈；
- 桌面高 DPI、浏览器和静止阅读模式分别完成截图与交互回归。

## 7. 推荐执行顺序

先完成 P0 并建立自动性能基线，再进入 P1。P1 的锚点发布和关系层改造是核心收益来源。P2 可以和接口测试并行推进。P3 必须建立在已有档位可独立工作的前提上，避免治理器掩盖底层缺陷。
