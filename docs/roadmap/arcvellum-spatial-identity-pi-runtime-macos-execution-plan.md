# ArcVellum 空间视觉、Pi Runtime 与 macOS 交付执行方案

状态：执行中  
适用基线：`f5f904c` / `0.99.2` 开发分支  
参考实现：`arcvellum-orrery-demo`，只吸收相机、投影、缓动和交互思想，不复制演示数据或页面结构。

## 1. 目标与边界

本轮不是一次字号热修，而是把叙事星仪从“可用的项目图”收敛成 ArcVellum 的品牌主界面，同时完成 Agent Runtime 的依赖收敛和 macOS 发布准备。

必须交付：

1. 全书视图中章节、场景和当前创作信号在常用桌面尺寸下可辨、可读、可操作。
2. 节点不再因为自动全书适配而一起缩成微缩图；信息通过连续 LOD 分层呈现。
3. 章节节点移除环绕星环，以单一、有记忆点的“章节航标”视觉取代。
4. 主脉、章节簇、场景局部关系和当前任务形成明确的空间层级与色彩层级。
5. 所有浮动窗口逐项通过内容完整性、滚动、缩放、拖动、全屏、主题一致性和遮挡验收。
6. Pi Worker 继续成为默认、专业、受控的文学执行器；OpenCode 从“安装包硬依赖”迁为可选兼容适配器。
7. 建立可重复的 macOS 双架构构建链。无 Apple 凭据时产出 CI 可验证的 ad-hoc 签名预览包；正式分发仍要求 Developer ID 和 notarization。

不在本轮做：

- 不重写 CLI 文学工程状态机。
- 不用自由力导向图替代稳定叙事布局。
- 不把星仪做成纯装饰或真实 3D 游戏世界。
- 不在 Pi 功能等价前直接删除 OpenCode 代码。

## 2. 基线问题审计

### 2.1 星仪

当前截图暴露的是一组相互放大的问题：

- 全书 `fit` 同时受超长横向脊线和较低视口高度约束，导致摄像机比例过小。
- DOM 节点继续乘以深度比例；`overview` 又隐藏节点文案，用户只能看到微弱点阵。
- 章节主脉使用单一金色，任务、人物、正文和 Gate 缺乏稳定的色彩身份。
- 章节曲线可读，但横向占据过长，视觉能量集中在细线而不是章节航标。
- 上方创作进阶星链与下方作品脉络尺寸相近，争夺主视觉层级。
- 星空天幕有深度，但缺少能成为品牌记忆点的“叙事极光、远景星云、局部引力亮区”。
- 章节节点的多重圆环叠加了 DOM、Pixi 和关系层视觉，产生三层几何形状。

### 2.2 窗口

现有窗口具备拖动、缩放、折叠和全屏，工程能力已经存在；问题是视觉与信息架构仍过于通用：

- 所有窗口共享近似头部与深色面板，任务个性不足。
- 小窗口中出现长说明、密集指标和重复标题，正文区域被压缩。
- 内容组件在浮动模式和全屏模式使用同一排版，没有容器级重排契约。
- 节点窗口、推进、Agent、决策、规则、交付、正文等高频窗口缺少各自的视觉焦点。
- 浮动窗口与背景色相近，但边界、深度和聚焦态区分不足。

### 2.3 Runtime 与发布

- Pi Worker 已具备多供应商模型、思考预算、会话标识、专业角色、工具租约、无进展保护、结构校验和流式事件，具备继续专业化的基础。
- OpenCode 仍被顾问、Creative Steward、文风工坊、作品反推、配置 API、生命周期和桌面资源直接引用，当前不能安全地只删二进制。
- Tauri 配置、Rust 启动器、资源路径、PyInstaller sidecar 和 GitHub Actions 均为 Windows 专用。
- Tauri 的 sidecar 必须为每个目标提供 `-$TARGET_TRIPLE` 文件；macOS 应由 macOS runner 构建，不能从当前 Windows 环境伪造最终安装包。

## 3. 视觉设计宪法

### 3.1 视觉方向

品牌母题：**活体叙事天文台**。

不是普通黑色 AI 控制台，也不是羊皮纸复古界面。用户看到的应当是：一部作品正在夜色中形成引力、脉络和光谱；工程证据则像精密仪器一样安静地围绕作品运行。

### 3.2 色彩角色

避免一切信息都落入金色。固定六种语义色：

- `Canon Gold`：章节、正式事实、交付。
- `Jade Current`：当前任务、可推进状态、活动会话。
- `Cinnabar Turn`：冲突、阻断、分支转向。
- `Iris Memory`：人物、记忆、关系。
- `Azure Evidence`：审查、证据、读者问题。
- `Mineral White`：正文与关键文字，不作为大面积面板底色。

背景维持午夜蓝绿，但加入低饱和靛青和朱砂局部光域，让画面有记忆点而不是变成彩色噪声。

### 3.3 信息层级

采用三层连续 LOD，不再用一个阈值突然把文字全部隐藏：

1. `far`：章节航标、章节序号、完成亮度、主脉；场景仅保留星点和簇轮廓。
2. `mid`：章节标题、场景短名、当前任务状态；人物和证据显示类别色。
3. `near`：完整标题、副说明、正文/字数、关系与交互动作。

固定屏幕尺寸最小值：章节航标 22px，场景航标 14px，其他交互节点 12px；文字不随深度无限缩小。

### 3.4 章节航标

移除章节外环和装饰轨道。新航标由三部分组成：

- 单一发光核心；
- 与阅读顺序相切的短刻度；
- 可读章节序号和标题。

已完成章节稳定发光；未完成章节降低核心亮度但保持轮廓可见；当前章节产生缓慢脉冲，不旋转、不闪烁。

## 4. 星仪算法实施

### 4.1 相机与适配

修改 `parallaxRenderer`：

- `fitBook` 不再让极端横向范围把整张图压扁；引入语义窗口和最小可读比例。
- 默认开场优先覆盖当前章节前后邻域，同时保留远景章节上下文。
- 用户点击“完整显示”时才进入真正全书远景。
- 沿用四元数姿态和无角度限制的中键视角，但节点屏幕 LOD 与世界深度解耦。
- 参考 demo 的缓动思路，为节点和相机保留独立目标值，聚焦时使用非线性推进而不是瞬移。

### 4.2 布局

保持稳定、确定性、按作品逻辑布局：

- 章节核沿开放的节奏样条推进，不闭环、不绕圈。
- 样条弧长按时间跨度与节奏权重共同分配；时间跨度决定前进距离，节奏强度决定曲率和局部起伏。
- 同章场景围绕章节核形成小型扇形/花序簇，场景间距设置屏幕可读下限。
- 人物节点位于其参与章节簇的加权重心外侧；承诺、问题、分支、审查靠近真实关联场景。
- 局部碰撞松弛只移动卫星节点，不迁移既有章节主脉。
- 长篇项目分段渲染标签，但不删除节点或章节。

### 4.3 连接与动态

- 章节主脉使用带呼吸感的 cubic Bézier / Catmull-Rom 转 Bézier 曲线。
- 章节到场景是较细的引力弦；场景到分支、承诺、问题、审查使用语义色。
- 完成区段亮、未完成区段暗；聚焦章节时主脉退为背景，章内关系增强。
- 当前任务沿关系线产生一次性流动信号，不让全部曲线永久跑马灯。
- 星空天幕增加两处固定品牌光域和一条低对比叙事尘带；运动只响应相机和微弱时间，不跟节点平移。

## 5. 窗口逐项重构与验收矩阵

通用框架改造：

- 统一 6px 以内圆角、半透明矿物黑玻璃、内描边和受控阴影。
- 头部高度压缩，标题、状态和操作同一行；图标按钮固定尺寸。
- 浮动前后尺寸一致，拖动不改变布局；内容区始终可滚动。
- 使用 container query 为紧凑、标准、宽屏三种布局重新排版。
- 聚焦窗口提高亮度和色彩，非聚焦窗口降低对比但不消失。

逐项标准：

| 窗口 | 主视觉 | 必须可见 | 紧凑行为 |
|---|---|---|---|
| 节点 | 类型色航标 | 完整标题、状态、关键指标、关系、动作 | 关系列表滚动 |
| 推进 | 当前执行脉冲 | 模式、任务、进度、错误、控制 | 说明折叠，操作固定底部 |
| Agent | 会话灯阵 | 当前任务、会话、上下文/用量、事件 | 会话与事件分栏切换 |
| 决策 | 选择卡 | 原因、影响、选项、已提交状态 | 一次只展开一个决策 |
| 规则 | 节奏曲线 | 文风、字数、节奏、Lint、保存状态 | 标签页固定，内容独立滚动 |
| 交付 | 交付信标 | Gate、文件、大小、下载/准备 | 文件列表滚动 |
| 正文 | 纸张光域 | 章节目录、已晋升正文、阅读位置 | 默认纵向阅读，支持沉浸 |
| 档案 | 深色 IDE | 树、编辑器、状态、晋升动作 | 文件树可收起 |
| 文风 | 光谱指纹 | 语料、学习状态、挂载、提示词 | 步骤式工作区 |
| 质量 | 编辑仪器 | Lint、Review、阈值、预览 | 问题列表与配置分栏 |
| 策略 | 路线星盘 | 全书目标、DAG、节奏、字数 | 摘要固定，详情滚动 |
| 观测 | 运行示波器 | 会话、事件、耗时、上下文、失败 | 实时流区域滚动 |
| 考古 | 地层剖面 | 输入、提取进度、候选资产、晋升 | 阶段导航固定 |

视口：`1280x720`、`1440x900`、`1920x1080`、`390x844`。每种视口至少检查：默认、最小尺寸、用户拖动后、全屏、内容溢出。

## 6. Pi Worker 专业化与 OpenCode 解耦

### 6.1 统一接口

建立 `AgentRuntimeGateway`：

- `execute(task_package, profile, session)`
- `stream_events(run_id)`
- `cancel(run_id)`
- `health()`
- `model_catalog()`
- `credential_contract()`

所有业务模块只依赖 Gateway，不直接 import OpenCode server/client。

### 6.2 Pi 专业化

- Advisor：自由对话、项目只读检索、结构化指令建议。
- Steward：代理用户决策，但受策略和审计记录约束。
- Style Scholar：语料分析、提示词归纳、挂载审查。
- Archaeologist：长文分块抽取、实体归并、候选资产生成。
- Writer/Reviewer/Planner：继续使用现有严格工具租约和任务包。
- 为每种角色配置持久系统契约、短任务 delta 和独立思考预算，避免每轮重复注入整套 Skill。

### 6.3 迁移顺序

1. Gateway + Pi adapter，保持当前主创链不变。
2. 迁移 Advisor 和 Steward。
3. 迁移 Style 与 Archaeology。
4. 配置、观测、模型目录改用中性 runtime API。
5. OpenCode 改为用户可选外部适配器。
6. 桌面资源与构建默认不再捆绑 OpenCode。
7. 保留一轮兼容版本和迁移提示；等价测试通过后再清理遗留别名。

## 7. macOS 交付链

### 7.1 平台抽象

- Rust 启动器按平台解析 `node`/`node.exe`，不再硬编码 OpenCode 路径。
- sidecar 由对应 runner 用 PyInstaller 构建，并按 Tauri target triple 命名。
- Pi Worker bundle 为 macOS 准备 Node arm64/x64 runtime，或直接使用项目内受控 Node sidecar。
- Tauri 资源清单仅包含 Pi Worker 与 demo project。
- 图标增加 `.icns`，bundle target 支持 `app,dmg`。

### 7.2 CI

- Windows：`windows-latest / x86_64-pc-windows-msvc`。
- macOS Apple Silicon：`macos-latest / aarch64-apple-darwin`。
- macOS Intel：`macos-13 / x86_64-apple-darwin`。
- 三个平台分别执行前端、Python、Pi Worker、sidecar provenance 和安装后 smoke test。
- 无 Apple Secrets 时使用 `signingIdentity: "-"` 产出预览包并明确标记；正式 Release 仅在签名与 notarization 成功时发布 macOS 稳定资产。

必要 Secrets：`APPLE_CERTIFICATE`、`APPLE_CERTIFICATE_PASSWORD`、`APPLE_SIGNING_IDENTITY`，以及 notarization 所需 Apple ID/app-specific password/team ID 或 App Store Connect API key。

## 9. 完成定义

只有同时满足以下条件才算交付：

- 常用视口截图中章节标题可读、场景簇可辨、当前任务明确、没有星环和三重几何叠加。
- 节点聚焦、章节跳转、中键视角、滚轮缩放、关系镜头和多窗口不互相破坏。
- 所有窗口没有裸白控件、内容裁切、拖动变形、不可达按钮或无意义空白。
- Pi Worker 能覆盖主创、审查、顾问、代理用户、文风和反推的正式调用入口。
- 默认安装和启动不依赖 OpenCode 二进制；选择 OpenCode 时有明确的外部安装提示。
- Windows 构建通过；macOS 双架构 CI 至少通过编译与 bundle。正式签名失败只能由缺少 Apple 凭据导致，不能由工程配置导致。
- Git 工作树干净，每个批次有可回滚提交，README 和发布资料与代码一致。
