## 1. 当前代码与批判性结论

| 现状证据 | 对体验的影响 | 决定 |
| --- | --- | --- |
| `project_agent/service.py` 的会话已持有 `project_root`；`useProjectAgentSession.ts` 却以全局 `currentProjectPath` 加载会话，`AgentWorkspaceView.vue` 顶部还能随时切换作品 | “对话属于哪部作品”不稳定，切换作品会重置会话 | 保留后端绑定；创建会话前选择作品，打开旧会话时以其绑定作品为准；不在会话中隐式改归属 |

| `AgentContextInspector.vue` 已有作品状态；完整观测另在 `AgentObservatoryView.vue` | 右侧状态重复，创作现场还要跳页 | 右侧做轻量 Worker 会话列表与当前任务，按需打开详情；诊断数据不塞满对话 |

| `engine/parallaxRenderer.ts` 在 full 动效下可因环境运动持续发布全量锚点；已有性能计划测得完整动效 P95 60.6ms | 桌面星仪掉帧 | 本轮先做动画预算、可见性暂停和静止锚点停止发布，记录基线；关系线和作品事实不可为性能而消失 |
| `AgentThreadRail.vue` 同时列创作策略、Agent 观测、作品库 | 功能看似很多，主任务难辨 | 撤掉冗余显性入口；旧深链安全重定向，后台能力保留 |
| `SettingsView.vue` 已有 API Key 表单和模型目录；启动后无显眼连接指引 | 新用户可能先碰到无法运行的 Agent | 首次进入检测真实可用连接，展示一次性连接引导并直达设置；允许浏览演示与修复，避免把只读路径锁死 |

### 必须避免的误改

1. 不把会话归属建立在 `localStorage`。那只是最近打开的作品；服务端 `session.project_root` 才是事实。
2. 不物理删除作品库、文风、考古或观测 API。此轮先调整导航和界面说明，旧链接保留可恢复路径。
3. 浅色星仪不是纯白背景。主线与节点需要足够对比；暗色线、朱砂状态、青绿关系与暖金已完成状态应各有职责。
4. 观测摘要优先读取现有 `agentObservability` 与会话流。不再建第二套轮询或运行状态模型。
5. 创作现场卡片只展示实际事件/候选，不把候选标为正式正文，也不向消息记录伪造 Agent 发言。

## 2. 目标交互

### 2.1 对话与作品

启动后直接进入会话桌面。新对话先选择现有作品，或进入作品管理建立、导入作品。会话一经建立即归属所选作品；首条消息之前也不能无声改绑。已经发送消息或正在运行的会话不可用顶部下拉直接切到另一部作品。点击历史会话时自动切到其服务端绑定的作品，并在右侧呈现对应状态。星仪入口位于当前会话标题区和右侧作品状态中；无作品会话不可进入。独立的无作品闲聊不属于本轮需求，暂不提供。

作品库仍可从选择器打开，用于创建、导入和管理。原 `/projects` 深链转入新会话选择器；已有老会话与作品不迁移数据。

### 2.2 两种主画面

Agent 桌面：左侧会话、中央对话/正在创作卡、右侧当前作品与 Worker 活动。右侧有总览与按需详情折叠。星仪：沉浸查看作品空间，其返回动作回到原会话。星仪只保留与空间探索直接相关的导航、聚焦、节点信息；重复的创作入口通过对话端承担。

### 2.3 首次连接

没有用户配置的可用凭证时显示清晰的“连接模型”首次任务，入口直接展开连接与模型。演示项目、已完成正文和帮助仍能只读浏览。表单保存成功后自动刷新模型目录并关闭提示，错误可重试，不记录密钥到浏览器存储。

### 2.4 创作现场与辅助区

进行中的主创活动在对话流中以可展开卡呈现：当前任务、角色、最近产出、打开完整现场。右侧用紧凑会话行展示 Worker 角色、状态、任务、最近事件；只有展开时才出现上下文/运行细节。文风与考古入口附“开发中，不完善”；保留它们已有的实际能力。策略页从导航中撤下，旧链接转质量/节奏或对话。

## 4. 实施批次与验收

1. **配图已完成**：隔离合成作品截取当前 Agent 与星仪实拍，README 引用；开发界面实拍须明确与已发布安装包的区别。
2. **对话归属**：会话创建选择作品；历史会话打开后归属准确；无作品/只读演示可辨；旧路径可访问。测试会话切换和作品切换不会把消息送到错误作品。
3. **右侧与现场**：右栏展示当前活跃 Worker 及最近事件；对话中的创作卡能打开现场。空闲与运行两种状态截图验收。
4. **浅色星仪与性能**：Web 与桌面大小视口截图；静止/运动/缩放/聚焦验证；对比已有 100/300/1000 场夹具的节点与关系数；记录动画对象数、首屏和帧耗时，达不到基线时不宣称优化成功。
5. **连接与导航**：新用户先看到 Key 引导；保存连接后正常进入对话；文风/考古标注、策略入口清除、旧路由安全。
6. **收尾**：定向单测、客户端构建、真实浏览器截屏、`git diff --check`；修正 README 截图。提交和推送按仓库分支与发布状态单独决定，不把通过 Web 验收等同于桌面发行验收。

## 5. 设计语言

与用户提供的对话截图同一信息层级，但保持 ArcVellum 自身识别度：主体使用温和的纸白与石墨色，右栏用微暖灰，任务推进用青绿，待处理用朱砂，作品完成用钝金。星仪改为“白昼天文台”：冷白至浅青灰的低噪天幕承托真实章节与关系；线条和节点比背景更有存在感。对话区不用大面积装饰卡，不用星仪的交互密度干扰阅读。字体以 12-15px 的常规中文正文为下限，稠密信息在详情层展开。

## 6. 明确的范围与风险

本轮不改长篇文学内核、不迁移数据库、不新增模型供应商、不删除 API。对话横跨项目的近况列表可以先通过现有逐项目查询建立，再在真实大作品库出现性能问题时统一后端索引；不提前引入搜索服务。星仪性能改动只处理已经测出的高成本路径，不引入通用 PerformanceGovernor 作为新框架。若视觉验收发现浅色天幕削弱主体连线，需要先调整对比与层级，再谈装饰。

### 验收与未完成项

- 客户端 224 项单测、TypeScript 检查和生产前端构建通过；10 项 Playwright 用例串行通过，覆盖新对话跨作品绑定、创作现场的真实入口与全屏、星仪 100/300/1000 场景布局和千场景交互。README 截图来自可运行的 Web 客户端。
- 复核时修正了两处真实界面问题：会话初始化早于作品目录导致的归属竞态；创作现场在星仪浮动窗口中因旧最小高度遮挡标题。旧的悬浮顾问验收项已改为当前“从星仪返回对话”交互，并让模拟 SSE 遵守取消信号。
- 参考图的三栏信息层级已用于正式界面；截图仍是空会话状态，不能证明长会话、密集工具事件和各种失败状态都达到同样视觉质量。
- 空作品库、断连、模型凭证保存后的真实桌面端首启流程，还需要独立安装矩阵验收。不能把本轮 UI 收敛表述为新的稳定发行版。
- 与作品关联的旧 URL 保持兼容；今后删除旧页面或 API 必须先确认没有用户书签、历史会话或内部调用依赖。
