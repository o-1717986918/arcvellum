# ArcVellum v0.98.0

ArcVellum v0.98.0 turns the Pi-based literary Worker from an isolated experiment into a bundled, user-selectable ArcVellum runtime. The literary workflow, task ownership, deterministic gates, and formal project state remain owned by Studio; Pi executes one bounded task package at a time and cannot bypass promotion or writeback rules.

## Built-in Pi Worker

- The Windows installer carries a fixed Node runtime, the compiled ArcVellum Pi Worker, its production dependency closure, licenses, and a digest-bound installation receipt.
- Users can enable Pi, select a supported `provider/model`, test readiness, choose a reasoning preset, and assign it to future creation tasks without installing Node or a separate Agent platform.
- Pi receives a narrow Worker profile, a task-scoped contract, an exact read allowlist, and explicit expected outputs. It has no shell, Git, arbitrary-network, or unrestricted project access.
- Studio remains responsible for sandboxing, deterministic preflight, bounded repair, writeback approval, task completion, route audit, promotion, state application, Canon application, continuity, budget, and recovery.

## Prompt engineering

The model-facing prompt stack was audited from Prompt Asset through TaskPackage, evidence compiler, Worker profile, repair turn, and stop semantics.

- A real prose prompt fell from 189,908 to 29,218 characters, a reduction of about 84.6%.
- Host instructions such as `SKILL.md`, platform-Agent lifecycle, CLI commands, and embedded `[AGENT_TASK]` blocks no longer enter Pi prompts.
- Exact prose/review candidates and high-risk literary evidence remain lossless; unrelated implementation documents and recovery sidecars are on-demand.
- Repair turns carry only failed targets, relevant excerpts, and the still-valid contract rather than replaying the original prompt.
- Writer and reviewer roles stay isolated. Provider-level cross-task session reuse remains deliberately disabled until a separate invalidation contract is proven.

## Reliability and architecture

- Candidate, review, completion receipt, promotion, state, Canon, and continuity ownership are explicitly separated.
- Studio canonicalizes machine facts such as IDs, paths, digests, schemas, and session identities instead of asking a model to reproduce them.
- Invalid output receives a bounded validation-guided repair turn; unchanged failure digests stop instead of consuming unbounded requests.
- Architecture debt decreased from 38 to 33 oversized files and from 230 to 201 oversized functions. The repository remains at zero import cycles, forbidden dependencies, duplicate routes, and parse errors.
- DOMPurify and affected transitive dependencies were updated within compatible version ranges; `npm audit` reports zero known vulnerabilities for the release lockfile.

## Boundaries

- Pi is a formal optional runtime, not a silent replacement for every configured runner.
- Model credentials and inference remain user-managed. The installer does not contain a provider key.
- Provider-level persistent literary sessions and Pi subagents remain future work; v0.98 favors bounded, role-isolated sessions with explicit evidence.
- Formal Canon, state, continuity, promotion, and release still require deterministic contracts even in full-auto mode.
- The continuous literary acceptance used the product API and bundled Pi runtime from a clean project. Packaging was then verified independently through the release-layout Worker receipt, executable probes, and desktop-sidecar lifecycle smoke test; it was not rerun through an installed copy of the GUI.
