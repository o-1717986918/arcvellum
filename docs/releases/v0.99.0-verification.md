## 发布后 CI 收敛

标签工作流成功发布附件后，主分支 Linux CI 暴露了一个工作流隔离问题：Python 集成测试要求发现源码目录中的 Pi Worker 构建，但该独立 Job 没有先构建 Worker。与此同时，Windows Release 的多命令 PowerShell 步骤没有显式启用原生命令失败即停，存在前序命令失败被后序成功退出码掩盖的风险。

主分支后续提交只修正 CI：Python Job 在测试前构建 Pi Worker；Release 的安装、版本、Python、Vue、Worker 与打包步骤启用 `$PSNativeCommandUseErrorActionPreference`。它不改变 `v0.99.0` 产品源码、二进制或已发布标签，但让后续发布门禁对任一原生命令失败都真正失败关闭。

严格重跑随后确认 1274 项 Python 测试与架构审计全部通过，但模块地图检查发现旧生成器会把本机残留的、Git 不跟踪的空 Feature 目录计入结果，导致开发机与干净 Linux checkout 生成不同地图。后续修正将模块计数绑定到 Git 跟踪的源码集合，并固定生成文件使用 LF；没有 Git 元数据的临时测试目录仍使用忽略空目录的文件系统回退。
