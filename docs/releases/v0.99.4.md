# ArcVellum v0.99.4

ArcVellum v0.99.4 让漫长的 Agent 创作过程变得可见。新的“创作现场”把当前文学任务、候选正文、审查证据、修订差异、Agent 会话和用量组织在同一张工作面上；叙事星仪与阅读器也会响应同一份项目状态。

## 面向创作者

- 从星仪的“现场”入口查看正在处理的任务、候选产物和当前阻塞。
- 候选正文形成时可以提前阅读；它仍有明确的临时身份，不会混入正式长卷。
- 审查意见、修订版本与正式晋升沿同一产物身份链展示，能够回答“为什么改”和“改的是哪一稿”。
- Agent 会话、工具活动、上下文摘要、Token 与成本可以按需展开，默认界面继续使用读者能理解的创作语言。
- 创作现场在全屏与浮动工作台中均完整利用可用高度，正文列与证据列独立滚动。

## 实时链路

- 新增 `Creative Live Event v1`，统一手动 Worker、Autopilot、Pi Worker 与前端的活动、产物、Review、会话、用量和控制事件。
- Pi Worker 能从 `write_expected_output` 工具参数流中提取有界候选预览；Provider 不提供工具参数流时，退化为完整 snapshot。
- 新增项目级 Snapshot、SSE、会话与修订 API，并支持 `Last-Event-ID: live:<sequence>` 精确续传。
- 30,000 字符候选通过前端投影压力测试；同一候选的预览、写入、Review、修订、回执和晋升由 exact digest 关联。
- 创作现场断线不会影响 Worker、预检、写回和 Promotion，重连时由快照恢复最终内容。

## 正式身份边界

- Reader、导出、Canon 与人物状态继续只读取已晋升正文。
- 流式预览不会逐 Token 写入项目文件，也不会进入 SQLite 持久事件。
- 前端不能根据动画、字符数或事件名自行宣告晋升；正式状态仍由 Engine receipt 与 Gate 决定。
- 星仪只用实时事件标亮当前节点和关系，不改写节点的正式生命周期。

## 工程与发布

- OpenAPI 导出固定读取当前工作树，避免开发机上其他 editable install 污染生成合同。
- Playwright 将高压力星仪画布与创作现场画布隔离到独立浏览器进程，降低 Windows WebGL 驱动上下文累积造成的假性卡死。
- Python、Vue、Pi Worker、Rust、OpenAPI、架构审计与视觉验收均进入发布矩阵。
- Windows 安装包继续内置 frozen Studio sidecar、Pi Worker 和固定 Node 运行时；macOS Apple Silicon/Intel 继续发布未签名预览包。

## 升级说明

Windows 用户可运行 `ArcVellum_0.99.4_x64-setup.exe` 覆盖升级。作品库、模型凭证和项目目录不会被安装程序删除。升级后打开任一作品，在星仪右侧的“现场”入口即可查看实时创作过程。
