# ArcVellum v0.99.8

v0.99.8 把 lean-v2 长篇创作内核设为新项目的正式默认方案，并集中修正真实五章长篇验收暴露的场景分工、连续性、文风和作者沟通问题。它不以增加门禁或机械追逐字数为解法：软性的文学约束进入规划、生成与审读，违禁表达和标点规范仍由确定性检查负责。

## 面向创作者

- 顶层 Agent 在创作前和章节完成时说明故事进展、人物立场、已兑现与未决线索以及下一章压力，不再只报告任务数量。
- 项目 Agent 的正文进度改用正式正文字符数计算；流程完成、正文规模、文风预设评估与整书审读不再混为同一结论。
- 创作现场把运行事件转换为可理解的阶段、结果和恢复建议；长会话列表、同名作品选择、中窄窗口与手机宽度布局得到收束。
- 交付入口区分“尚无正文”“作品仍未完成”“存在正式阻断”和“可以交付”，但最终发布权威仍由后端正式路线掌握。

## 长篇创作与连续性

- 场景合同只把本场目标、参与者、冲突与后果交给本场；章节级承诺不再被复制成每场都必须提前兑现的事件。
- 生成与复核读取上一场正式正文，禁止重演首次见面、同一次取件、发现、交付、问答或决定，也禁止未列入参与者的人物提前进入。
- 每次正式场景提交会原子写入正文、SceneDelta、连续性投影、Canon 候选、时间线和提交回执；同一称谓被用于不同身份时会留下可见冲突证据。
- 每章只产生一个与正式场景修订集绑定的检查点；事件携带章节 ID 和作者摘要，返修轮数也进入顶层运行投影。
- 发布前生成独立的 `workflow/book_actuals.json` 正文实绩快照。规划预算继续作为基线保存，不再被误读为当前成稿统计。
- 分章导出由导出器统一拥有章号，避免“第1章 第一章”式重复标题。

## 文风系统

- 默认文风参考库使用用户提供的全部公版与原创样本，按叙述距离、句法、对白、节奏和场景功能组织；`r17` 至 `r25` 保持为正向参考。
- 无关精确数字采用严格的生成期默认规则：只有确实改变选择、因果或后续兑现的精度才保留；陈设件数、普通动作次数和装饰性时长改写为状态、阻力或结果。
- 人物声音要求由欲望、回避、知识边界和说话方式区分；规划与生成同时限制程序动作、模板句法、解释性收束和景物强制同步的累积。
- 标点规范错误与违禁表达继续阻断写回；短句、逗号链、破折号密度和转折节奏作为生成与审读证据，不被悄悄升级成第二套硬门禁。

## 工程与兼容

- lean-v2 成为新项目的生产默认内核；strict-v1 仅保留历史兼容读取，不再作为用户可选写入路径。
- 新的 `npm run dev` 会校验当前 checkout、版本和 `.venv` 后再启动隔离开发板，避免前端误连另一份旧 API。
- Windows 安装包继续内置 Python 服务、文学内核、Pi Worker 与演示项目；同一标签工作流构建 Windows 签名更新包和两种未签名 macOS 预览包。

## 升级说明

Windows 用户可运行 `ArcVellum_0.99.8_x64-setup.exe` 覆盖升级。既有作品继续保存在用户数据目录；历史 strict-v1 作品可读，新的正式创作默认进入 lean-v2。
