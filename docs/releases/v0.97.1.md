# ArcVellum v0.97.1

ArcVellum v0.97.1 是一次以长篇创作稳定性、Agent 执行吞吐和工程收敛为核心的维护版本。它延续 v0.97.0 的文学工程 Gate，不放宽正式正文、审查、晋升、状态写回与 Canon 写回边界。

## Agent 执行链路

- 将平台 Agent 需要完成的语义产物与 Worker 生命周期收据分离，避免任务包要求模型伪造运行状态。
- 任务提示词只投影当前任务真实获准读取的资料；沙箱许可与提示词资料表保持一致，减少反复读取被拒绝、无产物退出和确定性预检失败。
- OpenCode Runtime 拆分等待、超时和失败分类职责，按 worker、reviewer、planner、advisor、steward 使用不同的首事件与事件间超时。
- 对流式响应中断、事件静默和可恢复预检故障提供可审计的有限恢复路径，不让同一失败无限空转。
- 禁止跨任务复用不安全会话，同时保留满足租约和上下文指纹条件的安全复用能力。

## 长篇规划与文学契约

- 长篇字数预算任务只读取完成当前规划所必需的上下文，提示词体积显著下降。
- 章节义务使用独立 Prompt Asset，补齐章节目标、场景库存、节奏、字数和承诺兑现之间的显式契约。
- 角色、分支、正文、修订、AgentReview、状态与 Canon 的既有正式门禁保持不变。
- 强化分支义务传入正文、修订反规避证据与跨题材 composition rubric，防止效率优化稀释文学质量。

## 工程与产品稳定性

- 分解自动推进、任务认领、Worker 观察、候选晋升、状态投影和持久化仓储中的大职责，降低模块耦合。
- 清理无法跨安装或迁移复用的 `engine.python` 本机路径；源码运行和冻结桌面 sidecar 均选择当前有效执行环境。
- 补齐 Campaign 恢复、断线续传、上下文缓存、资源租约和进度检查点的生产接线。
- 成熟功能通过兼容性审计后进入正式产品面，未成熟策略与观测页面继续保持受控。

## 验证范围

- Python 全量测试、架构审计、版本同步、Prompt Registry 与确定性 Prompt Evaluation。
- Vue 单元测试、TypeScript 类型检查和 Vite 生产构建。
- Rust `cargo check --locked`、冻结 Python sidecar、Tauri Windows x64 安装程序、updater 签名、`latest.json` 与 SHA-256 校验和。

## 已知边界

- ArcVellum 仍处于 Beta；真实长篇无人值守运行仍受模型服务质量、速率限制和用户配置影响。
- 正式发布后仍建议在独立 Windows 10/11 环境验证首次安装、从 v0.97.0 覆盖升级、应用内更新和卸载。
