# ArcVellum v0.99.5

ArcVellum v0.99.5 收紧了文学工程内核与 Agent Runtime 之间的边界。创作任务现在以强类型协议和结构化 Engine Operation 流转，Pi Worker 成为桌面端唯一内置的正式 Agent 执行器；历史 OpenCode 产品依赖已经退出普通安装包。

## 面向创作者

- Windows 安装包随附《我胆小如鼠》授权演示文学项目。首次启动且作品库为空时，应用会自动安装并打开演示副本，读者可以直接查看星仪、人物、世界观、章节与正文组织方式。
- 既有作品继续兼容读取；项目 schema 可以先预览、备份，再执行有界迁移，重复迁移不会制造额外变化。
- 模型设置统一归入 Pi Worker。旧配置里的 OpenCode Runner 和模型连接记录会在加载边界被忽略，不再回到已退役的默认模型。
- Provider 余额、额度或连接失败会暂停并保留进度，不会无限重试消耗费用。

## 任务协议

- 新任务默认采用 `arcvellum/task/v2`，把不可变任务规范、可变生命周期、资源引用和 Route 扩展明确分区。
- Studio 通过结构化 Engine Operation 调用内核，不再反解析正式 Shell 命令；旧 v1 命令只在受控兼容边界升级。
- 七条正式 Route 共用 Task Builder，字数、输入、输出、完成回执和写回边界由一套协议生成。
- 旧 v1 TaskPackage、历史项目身份和受支持的顶层兼容入口仍可读取，并有语义 fingerprint 与回归测试保护。

## Pi Worker

- 大体积结构化 JSON 可以通过专用上限写回，不再被正文文本分块上限误伤。
- 兼容供应商自动附带空参数占位时，Worker 可以识别真实输出，仍会拒绝同时提交两份非空内容。
- 资产审查、文风评估和修订任务增加有界字段规范化；冲突判断继续 fail closed，不替 Agent 猜测结论。
- 普通安装内置 Pi Worker、固定 Node 运行时和受控任务沙箱，无需另行安装 OpenCode。

## 工程收敛

- 正式 CLI 帮助、运行资源和产品文档移除退役命令与历史 Agent 身份。
- Engine 公共 API、兼容 facade 与 schema 别名拥有显式清单和移除窗口。
- 架构基线收敛到 12 个历史大文件、80 个历史复杂函数，保持零循环依赖与零新增边界违规。
- OpenAPI、Vue 类型、Python sidecar、Pi Worker、演示包、Tauri 安装器和 updater 清单继续由同一发布流水线生成并校验。

## 升级说明

Windows 用户可以运行 `ArcVellum_0.99.5_x64-setup.exe` 覆盖升级。作品、模型凭证和项目目录不会被安装程序删除。应用升级后会保留已有作品库；只有空作品库会自动安装随包演示项目。
